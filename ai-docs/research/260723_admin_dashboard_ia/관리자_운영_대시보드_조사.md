# 관리자 운영 대시보드 조사

> 대상: Saigon Rider Operations Console `운영 현황`  
> 결론: 이 화면은 **KPI gallery가 아니라 operations cockpit(운영 관제 시작점)**이어야 한다.

## 1. 조사 질문과 결론

### 화면이 답해야 할 질문

1. 지금 즉시 확인하거나 처리할 일이 있는가?
2. 서비스와 운영 흐름은 평소 범위인가?
3. 어떤 영역이 변했으며, 왜 상세 화면으로 들어가야 하는가?
4. 다음 행동으로 한 번에 이동할 수 있는가?

현재 화면은 네 질문에 필요한 데이터의 상당 부분을 이미 갖고 있다. 문제는 지표 부재보다 **모든 항목을 비슷한 카드로 나열한 정보구조**다. 따라서 1차 개선은 신규 백엔드 통계 추가보다 기존 응답의 우선순위화·그룹화·축약에 집중한다.

## 2. 현재 화면 진단

첨부 화면에서 확인되는 구조:

- 상단 대형 카드 4개: 미처리 신고, 미답변 문의, 파트너 심사대기, 광고 심사대기
- 하단 동일 계열 카드 다수: DAU, 신규 가입, 매물 등록, 거래 성사, 판매중 매물, 이용정지 계정, 첫 응답 SLA, 승인/신규/정지 파트너, 론칭중/등록 광고 등
- 대부분의 카드가 같은 테두리·높이·숫자 크기를 가져 중요도 차이가 약하다.
- `0건`인 정상/비활성 상태도 동일 면적을 차지한다.
- 오늘 값, 최근 7일 값, 누적/현재 재고가 같은 레벨에 섞여 있어 비교 기준이 불균일하다.
- 상단 카드에 `>`가 있지만 무엇을 우선 처리해야 하는지, 가장 오래 기다린 건이 무엇인지 드러나지 않는다.
- 숫자 변화의 기준선이 부족하다. 예를 들어 DAU `2명`만으로는 정상/이상 판단이 어렵다.
- 스크롤 아래로 갈수록 동일 카드가 계속돼 첫 화면에서 업무 우선순위를 형성하지 못한다.

즉, 문제는 카드 개수만이 아니라 **업무 큐·운영 건강도·현황 재고가 구분되지 않은 것**이다.

## 3. 근거 원칙

### 3.1 목표와 질문을 먼저 고정한다

Grafana는 대시보드가 하나의 이야기 또는 질문에 답하고, 일반→구체의 진행을 가져야 하며, 문제가 있는 항목을 중심으로 보여 인지부하를 줄여야 한다고 안내한다. 또한 계층형 drill-down과 링크가 유도하는 탐색을 권장한다.  
근거: [Grafana dashboard best practices](https://grafana.com/docs/grafana/latest/visualizations/dashboards/build-dashboards/best-practices/)

적용: 이 화면의 질문은 “전체 숫자가 무엇인가?”가 아니라 “오늘 어디부터 처리할까?”다.

### 3.2 중요도는 면적·대비·위치로 표현한다

Carbon은 중요 데이터가 가장 높은 대비와 큰 면적을 차지해야 하며, 지표 수를 제한하고 비필수 정보는 필요할 때만 제공하라고 한다. 여백은 관련 항목을 묶고 우선순위를 구분한다.  
근거: [Carbon — Dashboards](https://carbondesignsystem.com/data-visualization/dashboards/)

적용: 긴급 업무와 이상징후는 상단·고대비, 정상 재고/누계는 하단·저대비 compact summary로 둔다.

### 3.3 “건수”보다 처리 가능한 단위를 보여준다

Material의 data table 지침은 비교 가능한 정보를 의미 있게 정렬하고 alert·상호작용을 결합해 스캔과 행동을 지원한다. NN/g 역시 목록에는 다수 사용자가 판단하는 데 필요한 핵심 속성만 남기고 강조를 과용하지 말라고 한다.  
근거: [Material — Data tables](https://m2.material.io/design/components/data-tables.html), [NN/g — The Anatomy of a List Entry](https://www.nngroup.com/articles/list-entries/)

적용: 대기 카운트 아래에 모든 상세를 복제하지 말고, 가장 오래된/위험한 건 몇 개를 compact queue로 보여준다.

### 3.4 색은 상태 의미가 있을 때만 쓴다

Grafana는 색을 threshold 등 의미와 연결하라고 하고, Carbon은 데이터셋별 색 배정을 일관되게 유지하라고 한다.

적용:

- 빨강: SLA 초과, 즉시 조치가 필요한 미처리
- 주황: 임계치 접근/검토 필요
- 청록 또는 중립: 정상·정보
- `0건`은 성공을 강조하는 초록 대형 카드가 아니라 muted 상태로 처리
- 아이콘 배경색과 숫자색을 모두 강하게 칠하는 중복 강조는 피함

## 4. 권장 정보구조

### 4.1 1단 — 오늘의 운영 요약

페이지 제목 우측 또는 아래에 다음만 둔다.

- 데이터 기준시각: `마지막 업데이트 HH:mm`
- 갱신 행동: 새로고침 아이콘/버튼
- 필요 시 기간 기준: `오늘 · 최근 7일`

목적은 숫자의 신뢰 기준을 제공하는 것이다. 전역 기간 필터를 새로 만들 필요는 없다. 현재 API가 기간 전환을 지원하지 않으면 표시만 명확히 한다.

### 4.2 2단 — `확인 필요` 업무 큐

가장 큰 영역이며 기존 상단 4종을 사용한다.

권장 순서:

1. 미처리 신고
2. 미답변 문의
3. 파트너 심사대기
4. 광고 심사대기

표현 방식:

- 섹션 헤더: `확인 필요` + 총 대기 수
- 각 항목은 compact row 또는 2×2 action card
- 기본 정보: 업무명 / 현재 대기 건수 / 보조 상태 / `목록 보기`
- 가능하면 기존 데이터 범위에서 `오늘 접수`, `최근 7일 처리`, `승인/정지`, `론칭중`을 보조 문구로 유지
- `0건` 항목은 행 높이와 대비를 낮추되 섹션에서 제거하지 않는다. 제거하면 기능 진입점이 흔들리기 때문이다.
- 비영(非零) 항목을 먼저 정렬하되, 업무 유형 간 순서를 매번 크게 바꾸지 않아 근육 기억을 보존한다.

현재 스크린샷 예시:

- `미답변 문의 3건`이 첫 시각 강조 대상
- `미처리 신고 1건`은 위험도가 더 높을 수 있으므로 업무 중요도 기준으로 선두 유지 가능
- 두 심사대기 `0건`은 동일 대형 카드 대신 muted row

추가 API 없이 가능한 1차안은 “카운트+보조문구+링크”다. 개별 건의 경과시간/최장 대기값이 이미 API에 없다면 업무 큐 preview는 2차로 미룬다.

### 4.3 3단 — `운영 흐름` 핵심 지표

4개 이하의 compact KPI strip:

- 오늘 접속(DAU)
- 신규 가입
- 매물 등록
- 거래 성사

각 지표가 가져야 할 최소 문맥:

- 현재값
- 비교기간과 비교값: 현재 화면에 이미 있는 `최근 7일`을 명시
- 단위

비교값의 성격을 명확히 해야 한다. `오늘 0 / 최근 7일 3`은 “오늘 vs 7일 합계”라 직접 비교할 수 없으므로, UI 문구를 `오늘 0 · 최근 7일 누계 3`처럼 바꾼다. 증감률은 동일 기간의 이전 구간 데이터가 있을 때만 표시한다.

추세 차트는 다음 조건을 모두 충족할 때만 추가한다.

- 일자별 시계열이 이미 제공됨
- 비교 기준(이전 7일, 평균 등)이 정의됨
- 이상을 판단하거나 상세 진입할 이유가 생김

그렇지 않으면 장식용 sparkline보다 숫자와 기간 라벨이 낫다.

### 4.4 4단 — `운영 상태` compact summary

업무가 아니라 현재 재고/상태인 지표를 도메인별로 묶는다.

- 사용자: 이용정지 계정, 영구밴
- 마켓: 판매중 매물, 숨김
- 파트너: 승인 파트너, 정지 파트너, 신규 신청
- 광고: 론칭중 광고, 광고 등록
- 고객지원: 첫 응답 SLA(7일)

표현 방식은 2~3개의 작은 그룹 패널 또는 description list다. 개별 지표마다 카드 하나를 만들지 않는다.

예:

```text
파트너       승인 5   정지 0   신규 신청 0      →
광고         론칭중 31   신규 등록 0            →
계정 안전    이용정지 0   영구밴 0              →
마켓         판매중 166   숨김 0                →
```

이 구조는 현재 수치를 그대로 사용하면서 카드 수와 스크롤을 크게 줄인다.

### 4.5 상세 이동

- 숫자/행 전체를 클릭 가능한 링크로 만든다.
- 행 끝에는 일관된 `목록 보기` 또는 chevron을 둔다.
- 목적지가 없는 지표는 클릭처럼 보이지 않게 한다.
- 대시보드 내부에서 복잡한 필터/편집을 추가하지 않고 해당 관리 화면으로 보낸다.

## 5. 지표 선택 기준

대시보드에 남길 지표는 아래 중 하나 이상을 만족해야 한다.

1. **즉시 행동성**: 관리자가 지금 처리하거나 확인할 수 있다.
2. **이상 탐지성**: 기준선과 비교해 운영 변화/문제를 발견할 수 있다.
3. **핵심 흐름 대표성**: 가입→등록→거래 같은 서비스 흐름의 한 단계를 대표한다.
4. **상태 요약성**: 상세 페이지에 들어갈지 결정하는 현재 재고/상태다.
5. **명확한 소유권**: 해당 수치 변화에 대응할 운영 주체와 상세 목적지가 있다.

다음이면 제거 또는 하단 축약한다.

- 다른 지표와 의미가 중복됨
- 값이 변해도 관리자가 할 행동이 없음
- 기준 기간·단위가 불명확함
- 누계 숫자만 크고 운영 판단에 영향이 없음
- 상세 화면으로 갈 이유를 제공하지 못함

## 6. 디자인 적용 기준

현재 다크 콘솔의 디자인 언어는 유지한다.

- 기존 navy surface, 얇은 border, teal accent를 보존
- 새 색상 팔레트나 대규모 그래프 라이브러리를 도입하지 않음
- 카드 radius, border, typography token은 기존 컴포넌트에서 재사용
- 위계는 새 장식보다 면적·간격·타입 스케일·muted 상태로 만든다.
- 섹션 간 vertical spacing을 카드 내부 간격보다 크게 둬 그룹을 명확히 한다.
- 상단 `확인 필요`만 상대적으로 큰 패널, 나머지는 compact
- 같은 의미의 숫자/단위 정렬을 통일하고 `건/명/개/시간`을 숫자에 붙여 읽기 쉽게 한다.
- 좁은 화면에서는 업무 큐와 KPI strip이 1열로 접히되 정보 순서는 유지한다.

### 권장 데스크톱 배치

```text
[운영 현황]                         [마지막 업데이트 10:32] [새로고침]

확인 필요  4
┌ 미처리 신고 1 ─ 오늘 0 · 최근 7일 처리 0 ───── 목록 보기 ┐
├ 미답변 문의 3 ─ 오늘 0 ─────────────────────── 목록 보기 ┤
├ 파트너 심사대기 0 ─ 승인 5 · 정지 0 ───────── 목록 보기 ┤
└ 광고 심사대기 0 ─ 론칭중 31 ──────────────── 목록 보기 ┘

운영 흐름
[DAU 2] [신규 가입 0 · 7일 누계 3] [매물 등록 0] [거래 성사 0]

운영 상태
[파트너 요약] [광고 요약] [계정·안전 요약] [마켓 요약]
```

업무 큐를 2×2 카드로 유지해야 한다면 비영 항목만 높은 대비를 주고, `0건` 카드에는 낮은 surface와 짧은 높이를 적용한다. 다만 스캔과 세로 공간 측면에서는 row형이 더 적합하다.

## 7. 1차 구현과 후속 구분

### 1차 — 기존 데이터만 재배치

- 상단 4종을 `확인 필요` 섹션으로 통합
- 핵심 흐름 4개만 KPI strip으로 이동
- 나머지 지표를 도메인별 compact summary로 통합
- 기간 문구, 단위, 클릭 목적지, 업데이트 시각을 명확화
- `0건`과 비영 항목의 대비 차등

### 2차 — 데이터가 실제로 있을 때만

- 최장 대기시간 또는 SLA 초과 건수
- 업무 큐 상위 3~5건 preview
- 동일 길이 기간 대비 증감
- 일자별 시계열과 이상 annotation

2차 지표를 디자인 먼저 가정해 mock API나 백엔드를 확장하지 않는다.

## 8. 안티패턴

- 모든 지표를 같은 크기 카드로 만드는 KPI wall
- `0`을 포함한 모든 숫자를 큰 글자·색·아이콘으로 강조
- 비교 기준 없는 증감 화살표
- 데이터 포인트가 부족한 장식용 sparkline/donut/gauge
- 정상/경고/위험 의미 없이 도메인마다 다른 색 사용
- 같은 정보를 카드와 차트에 중복
- 대시보드 안에 상세 관리 기능·필터를 과도하게 복제
- 업무 우선순위와 무관하게 DB에서 쉽게 집계되는 숫자를 추가
- 실시간성이 필요하지 않은 지표를 고빈도로 새로고침

## 9. 명시적으로 제외할 것

- 매출·GMV·전환율 등 현재 화면/요청에 근거 없는 경영 KPI
- 사용자 지역·연령 등 분석용 세그먼트
- 시스템 CPU/메모리 등 별도 관측성 영역
- 랭킹, 목표 게이지, 예측치
- 커스터마이즈 가능한 위젯/드래그앤드롭 레이아웃
- 글로벌 기간 필터와 연동 차트

이들은 운영 시작점의 질문을 흐리고, 신규 데이터 계약 및 복잡성을 만든다.

## 10. 최종 권고

이번 개선의 성공 기준은 “카드가 예뻐졌다”가 아니다.

- 첫 화면에서 비영 대기 업무 2종(신고 1, 문의 3)을 즉시 찾는다.
- `0건`인 심사대기는 기능 진입점은 유지하되 시선을 빼앗지 않는다.
- 업무, 핵심 흐름, 도메인 상태가 세 섹션으로 구분된다.
- 오늘/최근 7일/현재 재고의 기간 의미가 섞이지 않는다.
- 각 행동 가능한 항목은 한 번에 해당 목록으로 이동한다.
- 기존 지표만으로 1차 구현되며, 신규 backend metric은 필요성이 검증된 2차에만 추가한다.
