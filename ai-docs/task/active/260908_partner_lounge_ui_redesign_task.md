파트너 라운지(`/biz/manage`)와 연결된 업체·광고·소식 관리 흐름을 실제 코드·현재 데이터 계약에 근거해 점검하고, 신뢰 가능한 개선 설계와 검토용 인터랙티브 시안을 만든다.

완료는 다음을 모두 만족할 때다.

1. 감사 결과가 화면·컴포넌트 또는 계약 근거, 영향도, 우선순위를 포함한다.
2. 설계 문서가 핵심 화면·상태·행동·빈/오류/제한 상태와 정보의 출처를 구분한다.
3. 시안은 독립적으로 핵심 흐름을 검토할 수 있고, 실제 서비스 데이터·결제·성과를 사실처럼 표현하지 않는다.
4. T1 리뷰가 감사·설계·시안의 불일치와 차기 구현 전제조건을 기록한다.

1. P1은 현행 화면과 연결 흐름을 감사하고 설계 문서에 결론을 남긴다. → 검증: 모든 우선순위 항목에 근거·사용자 영향·상태별 동작이 있다.

## 공통 제약

- 기존 디자인 시스템과 모바일 WebView 제약을 설계 판단에 반영한다.
- 성과·결제·광고 상태는 API가 제공하는 경우만 실제 값으로 취급한다. 그 외는 명확한 샘플·예시로 표기한다.
- 공유 워킹트리의 기존 변경을 보존한다.
- 제품 구현은 기존 프론트 API 계약 안에서만 수행한다. 배포와 DB 쓰기는 별도 검증·승인 전 수행하지 않는다.
