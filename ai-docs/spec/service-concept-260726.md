## 1. 한 문장 정의

> **호치민의 오토바이 세대를 위한 동네 중고거래 앱.**
> 거래는 대면 직거래가 기본이고, 앱은 **"만나서 주고받는 과정"** 을 오토바이 동선에 맞춰 돕는다.

돈·보험·배달망에는 개입하지 않는다. 수익은 지역 업체 광고.

**엘리베이터 피치**
"베트남에서 중고 물건을 사고팔 때 가장 귀찮은 건 물건 찾기가 아니라 *언제 어디서 만나느냐*다. 사이공라이더는 우리가 다 오토바이를 탄다는 사실을 전제로, 서로의 동선에서 가장 편한 지점과 시간을 잡아준다."

## 2. 타겟

### 2.1 왜 '오토바이'인가 — 핵심 인사이트

오토바이는 두 층위로 작동한다. 인터뷰에서 대표가 **둘 다**라고 확정했다.

| 층위 | 의미 | 제품에 미치는 영향 |
|---|---|---|
| **페르소나 수식** | 호치민 20~30대는 사실상 전원이 오토바이로 이동한다. "오토바이 타는 젊은이" = 이 도시의 보통 청년 | 브랜딩·톤·비주얼 언어. 기능 요구는 없음 |
| **실제 이동 수단** | 거래를 위해 실제로 오토바이를 타고 만나러 간다 | **거리·소요시간·동선·주차·안전한 만남 장소**가 핵심 UX가 된다 |

두 번째 층위가 이 서비스의 **유일한 구조적 차별점**이다. 물건 목록·채팅·찜은 누구나 만들 수 있지만, "오토바이로 만나는 과정"에 최적화된 중고거래 앱은 이 도시에 아직 정립되지 않았다.

### 2.2 페르소나 스케치

- **A. 대학생/사회초년생 (20~26)** — 예산 제약이 크고 중고에 거부감 없음. 오토바이 1대가 유일한 이동수단. 반경 5km 안에서만 움직이려 한다. 스마트폰은 중저가 Android, 데이터는 4G.
- **B. 직장 1~3년차 (26~32)** — 이사·이직으로 가구·가전을 처분/구매. 시간이 없어서 **"퇴근 동선에서 받을 수 있나"** 가 구매 결정을 좌우한다.
- **C. 동네 소상공인 (연령 무관)** — 정비소·부품점·카페. 광고주 후보이며, 동시에 **거래 거점**이 될 수 있는 존재.

세 페르소나 모두 공통적으로 **저사양 단말 + 불안정 4G**를 쓴다. 이건 디자인 제약으로 이미 코드에 반영되어 있다(blur·다중그림자·상시 transform 금지, 지도 목록 우선·lazy load).

## 3. 문제 정의

베트남 중고거래의 실제 마찰은 "물건이 없다"가 아니다.

1. **신뢰의 부재** — 판매자가 누군지 알 수 없다. 사기·노쇼가 흔하고, 그래서 거래 전 심리적 비용이 크다.
2. **만남의 마찰** — 채팅으로 "몇 시에 어디서"를 수십 번 왕복한다. 지명을 말로 주고받고, 막상 가보면 오토바이 세울 곳이 없다.
3. **거리 감각의 부재** — 목록에 뜬 물건이 나에게서 얼마나 먼지, 오토바이로 몇 분인지 모른다. "가까운 것 같아서" 문의했다가 왕복 1시간을 쓴다.
4. **정보 파편화** — 매물은 Facebook 그룹·기존 플랫폼에 흩어져 있고, 동네 가게 정보는 또 다른 곳에 있다.

**우리가 겨냥하는 것은 2와 3이다.** 1은 필수 위생 요소(신뢰 티어·신고·제재로 대응), 4는 부수 효과.

## 4. 경쟁 지형과 우리 자리

> ⚠️ 이 절의 시장 서술은 **미검증 가정**이다. 실제 착수 전에 현지 확인이 필요하다(§11).

| 플레이어 | 강점 | 빈틈 |
|---|---|---|
| 기존 대형 중고 플랫폼 (Chotot 등) | 물량·전국 커버리지·인지도 | 전국 단위라 "동네" 감각이 없다. 만남 과정은 채팅에 방치 |
| Facebook 그룹/Marketplace | 이미 다 쓰고 있고 무료 | 검색·필터·신뢰 장치 없음. 스팸. 지역 단위 관리 불가 |
| 배달 대행 (Grab·Ahamove 등) | 실제로 물건을 옮겨준다 | 중고거래 맥락이 없음. 유료. 소액 거래에 단가가 안 맞음 |
| 당근마켓 (한국, 직접 경쟁 아님) | 동네 기반 중고거래의 참조 모델 | 오토바이 전제가 아님(도보·자동차 문화) |

**우리 자리**: *동네 단위 + 오토바이 동선 최적화.* 물량으로는 대형 플랫폼을 못 이기고, 무료·관성으로는 Facebook을 못 이긴다. **한 개 구(區) 안의 밀도**로만 이길 수 있다.

## 5. 핵심 가치 제안 3가지

1. **"오토바이로 N분"** — 모든 매물·가게·약속에 나로부터의 오토바이 이동시간이 붙는다. 거리(km)가 아니라 시간(분)이 단위다.
2. **"만나는 걸 앱이 정해준다"** — 채팅 왕복 없이, 서로의 위치에서 합리적인 지점·시간을 앱이 제안한다.
3. **"우리 동네가 다 들어 있다"** — 매물 + 동네 가게 + 오토바이 생활정보(주유·침수·정비·유가)가 한 앱에.

3번은 이미 구현되어 있고, 1·2번이 앞으로 만들 것이다.

## 6. 서비스 구성

### 6.1 기능 지도

```
┌─ 코어 (서비스의 존재 이유) ────────────────────────────┐
│  매물 발견     목록·검색·카테고리·찜·지역 필터          │
│  거래 대화     DM · 가격제안 · 약속잡기                  │
│  만남 지원 ★   방향·오토바이 N분·만남 장소·도착 알림      │
│  평판          신뢰 티어 5단계 · 거래 완료 이력           │
└──────────────────────────────────────────────────────┘
┌─ 지원 (코어를 돕는 것) ────────────────────────────────┐
│  동네 가게     지도 핀 · 소식 · 후기 · 장소 제안          │
│  동네 소식     커뮤니티 피드                             │
│  생활정보      주유소 · 침수 · 정비소 · 날씨 · 유가        │
│  안전          신고 · 제재 · 모더레이션 · 금칙어           │
└──────────────────────────────────────────────────────┘
┌─ 수익 ───────────────────────────────────────────────┐
│  지역 업체 광고 (계정·심사·광고 CRUD·성과 대시보드)       │
└──────────────────────────────────────────────────────┘
┌─ 휴면 (건드리지 않음) ─────────────────────────────────┐
│  RP · 퀘스트 · 가챠 · 상점 · 인벤토리 · 시즌패스 · 라이딩 HUD │
│  → 코드·DB 보존, 진입점 닫힘. 되살리지도 정리하지도 않음    │
└──────────────────────────────────────────────────────┘
```

★ = 유일하게 미구현인 코어. 즉 **차별점이 아직 안 만들어져 있다.**

### 6.2 정보구조 (IA)

```
[현재]  홈 · 마켓 · 동네지도 · 커뮤니티 · 프로필
         ⤴월드맵      ⤴가게/소식/매물    ↑중복    ↑중복
         (게임 잔재)

[구상]  마켓 · 가게 · 소식 · 프로필
         ⤴첫화면  ⤴지도  ⤴피드
         ⤴ 상단 유틸리티 스트립: ⛽주유 · 🌧침수 · 🔧정비 · 💰유가
```

**중복의 정체**: 동네지도(`/map`)가 `가게 / 소식 / 매물` 3탭을 갖고 있고, 그 중 `매물`은 탭바 `마켓`과, `소식`은 탭바 `커뮤니티`와 같은 콘텐츠다. **하단 탭 5개 중 3개가 지도 안에 축소판으로 중복되어 있다.**

**홈의 문제는 다르다.** `/home`(월드맵)은 라이딩 게임앱의 첫 화면이고, 중고거래 앱의 첫 화면일 근거가 없다. 안에 든 실사용 가치(유가·날씨·침수·주유소·정비소)는 *첫 화면*이 아니라 *유틸리티*다.

2026-07-25에 `/map` 기본 탭을 `매물`→`가게`로 바꾼 것이 이 문제의 부분 인지였고, 위 구상은 그 방향의 완결이다.

## 7. 거래 라이프사이클 — 구현 현황과 갭

여기가 이 문서의 핵심 분석이다. 서비스를 단계로 쪼개면 **어디가 비어 있는지**가 정확히 보인다.

| 단계 | 사용자가 하는 일 | 현재 상태 |
|---|---|---|
| ① 발견 | 목록·검색·지도에서 물건을 본다 | ✅ 구현 |
| ② 판단 | 사진·설명·가격·판매자 신뢰도를 본다 | ✅ 구현 (신뢰 티어 5단계) · ⚠️ 번역 죽어 있음 |
| ③ 문의 | DM으로 묻고 가격을 제안한다 | ✅ 구현 (가격제안 수락/거절) |
| ④ 합의 | 언제 어디서 만날지 정한다 | 🟡 **약속 데이터는 있지만 "돕는" 기능이 없다** |
| ⑤ 이동 | 오토바이로 약속 장소까지 간다 | ❌ **없음** ← 차별점 |
| ⑥ 만남 | 물건과 돈을 주고받는다 | 🟡 상태 전이만 존재 |
| ⑦ 완료 | 거래 완료 처리, 평판이 남는다 | ✅ 구현 (완료 스냅샷) |

### 7.1 ④~⑤ 갭의 실체 — 생각보다 작다

`marketplace_appointments` 테이블에 이미 있는 것:

```
listing_id · conversation_id · proposer_id
when_at         (약속 시각)
place_name      (장소 이름)
place_lat/lng   (좌표)
status          (PROPOSED → …)
```

즉 **약속의 뼈대는 이미 서 있다.** 채워야 할 것은 신규 도메인이 아니라 그 위의 얇은 층이다.

| # | 구상 | 근거 자산 |
|---|---|---|
| 1 | **이동 방향** — 판매자가 가는지 / 구매자가 오는지 | 모델에 **없는 유일한 필드** |
| 2 | **🛵 N분 / 거리** — 약속 장소까지 | 마켓 목록의 기존 ETA 표기 재사용 |
| 3 | **만남 장소 제안** — 중간 지점, 오토바이 세울 수 있는 곳, 안전한 곳 | 지도의 가게 핀·ward 폴리곤 데이터 |
| 4 | **출발/도착 알림** — "상대가 출발했어요" | `noti_worker`(Redis Streams) 기존 인프라 |
| 5 | **가게 거점 (선택)** — 동네 가게를 안전한 인수인계 지점으로 | 이미 있는 `business_profile` 핀 |

**전제 조건**: 경로·ETA 기능은 코드가 완료되어 있으나 `GOOGLE_MAPS_API_KEY` 미발급으로 "준비 중" 폴백 상태다. **키 발급이 이 축의 출발점이다.**

**범위 한계 (대표 확정)**: 제3자 라이더 대행·자체 배달망은 만들지 않는다. 돈·보험·분쟁에 개입하지 않고 **당사자 돕기까지만.** 5번(가게 거점)도 "무인 보관함" 같은 책임 구조로 확장하지 않는다.

**미구현 확인**: `delivery|pickup|shipping|courier` 전수 검색 결과는 전부 휴면 게임 도메인의 퀘스트·아이템 문자열이었다. 실제 픽업/전달 코드는 **0**.

## 8. 수익 구상

**확정**: 지역 업체 광고 단독. 그 외는 미정.

광고 인프라는 이미 다 있다 — 비즈니스 계정·심사 큐·광고 CRUD·노출 게이트·성과 대시보드(노출/클릭/CTA 전환, CPM/CPC/CPA).

**따라서 부족한 것은 코드가 아니라 광고주다.** 현재 실제 계약 광고주는 0이며, 확보 경로도 미정이다.

지역 광고는 전국 트래픽으로 팔리지 않는다. **특정 구(區) 안의 밀도**가 상품이다. 그래서 순서는:

```
한 개 구 선택 → 그 구의 매물·유저 밀도 확보 → 그 구의 가게 10곳 → 실측된 단가로 상품 구성
```

이 검증 전에 광고 기능을 더 만드는 것은 순서가 거꾸로다. 거래 수수료·안전결제·상단노출 유료화는 **트래픽 검증 이후** 재논의한다(현재 결제·에스크로 코드는 없음 = 신규 구축 대상).

## 9. 신뢰와 안전

차별점은 아니지만 없으면 서비스가 성립하지 않는 위생 요소. 대부분 구현되어 있다.

- **신뢰 티어 5단계** — 매물 상세·프로필에 노출. (과거 "매너온도" 은유를 검토했으나 현지 정합성 문제로 티어 방식 채택)
- **신고·제재·모더레이션** — 매물 HIDDEN/REMOVED, 유저 제재, 정지 계정 차단, DM 금칙어, 감사 로그.
- **거래 완료 스냅샷** — 완료 시점의 합의 내용을 보존해 분쟁 시 근거로 삼는다.

**구상 단계의 미결**: 만남 장소를 앱이 제안한다면 **그 장소의 안전에 대한 책임 경계**를 어디까지로 볼 것인가. "제안"과 "보증"은 다르다는 표기 원칙이 필요하다.

## 10. 단계 구상

> 순서의 근거: **기능이 부족해서 못 나가는 게 아니다.** 막고 있는 것은 배포 정합·외부 키·외부 검증·법무다(§12).

| 단계 | 내용 | 성격 |
|---|---|---|
| **0. 눈으로 보기** | 미배포 작업물(디자인 전면 정비 143파일 + 지도 5화면 재설계) 배포 + DB 마이그레이션 적용 → 전 화면 순회 | 내부. **개선된 화면을 아직 아무도 본 적이 없다** |

## 11. 확정된 것 / 아직 가정인 것

### 확정 (2026-07-26 대표 인터뷰)

| 항목 | 결정 |
|---|---|
| 오토바이의 역할 | 페르소나 수식 **+** 실제 픽업/전달 기능, 둘 다 |
| 픽업/전달 범위 | **거래 당사자 돕기(경량)**. 제3자 대행·자체 배달망 없음 |
| 중심 축 | 마켓이 첫 화면, 탭 4개 (§6.2) |
| 수익모델 | 지역 업체 광고 단독. 그 외 미정 |
| 게이미피케이션 | 현재대로 휴면 보존 (되살리지도, 정리하지도 않음) |

### 아직 가정 — 확인이 필요한 것

1. **경쟁 지형(§4)** — 현지 실사용 데이터 없이 작성했다. 실제로 호치민 20대가 중고거래를 어디서 하는지 확인 필요.
2. **"만남의 마찰"이 진짜 1순위 문제인가(§3)** — 우리가 세운 가설이다. 유저 인터뷰로 검증되지 않았다. 만약 실제 1순위가 *신뢰*라면 차별점 축이 바뀐다.
3. **어느 구를 파일럿으로 할 것인가** — 미정. 대학가/신도심/전통 주거지 중 어디냐에 따라 카테고리 구성이 달라진다.
4. **광고주 확보 주체** — 대표 직접 / 현지 파트너 / 미정 중 **미정**.
5. **출사 시점·범위** — 미정. 웹 우선인지 네이티브 동시인지도 열려 있음.
6. **약속 장소 제안의 책임 경계(§9)** — 제품·법무 판단 필요.

### 그 외 구조적 잔재 (구상에 영향 있는 것만)

- **`Garage.tsx` 완전 고아** — 라우트 없고 import 0인데 `ItemDetail`·`Inventory`가 `/garage`로 navigate. 휴면 도메인 내부라 급하지 않으나, 게이미피케이션을 영구 폐기할 경우 정리 대상.
- **`spec/overview.md`가 원본 스펙으로 남아 있음** — 라이딩 게임앱 기준 27화면 문서. 새 인원이 이걸 읽으면 서비스를 오해한다. 이 문서가 그 위에 선다.
- **회귀 하네스가 WSL 전용** — Windows에서 지도 자동 회귀 실행 불가.

## 13. 한 장 요약

- 만들려는 것: **동네 중고거래 + 오토바이 동선 최적화**. 물량이 아니라 한 개 구의 밀도로 이긴다.
- 이미 있는 것: 발견·대화·평판·동네 가게·생활정보·안전·광고 인프라 — **거래 라이프사이클 7단계 중 5단계가 구현되어 있다.**
- 비어 있는 것: **④합의~⑤이동**, 즉 차별점 그 자체. 다만 약속 테이블이 이미 있어서 **작은 델타**다.
- 지금 필요한 것: 코드가 아니라 (a) 미배포분 배포해서 실화면 보기 (b) 지도 API 키 (c) 파일럿 구 선정 (d) §11의 가정 6개 검증.
