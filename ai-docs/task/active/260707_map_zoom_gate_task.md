## 원칙 점검 (service-rules.md GPS/위치 불변식)

| 아이디어 | 판정 |
|---|---|
| 일정 줌 이상에서만 리스트 조회, 미만이면 "확대" 가이드 | ✅ 정합 — 원칙 기본상태("지도: 구별 카운트 배지만 표시")와 오히려 일치. 전역 시트 리스트가 원칙 취지 이탈이었음 |
| 최초 진입 시 내 위치 중심 줌인 | ❌ **원칙 1·2 위반** (진입 시 GPS 자동 측정 금지, 명시적 선택 시에만) |

**절충**: 최초 진입 = 전역 배지 + 시트 가이드(확대 유도 + "내 동네 보기" = 기존 ◎와 동일한 명시적 GPS 액션). **재진입 시 마지막 뷰포트 복원**(localStorage)은 측정이 아닌 기억이므로 원칙 허용 — 사실상 두 번째 진입부터는 사용자가 원한 "내 동네 줌인 상태"가 된다.

## 목표 동작

1. **줌 게이트**: 구 집계 배지가 뜨는 줌아웃 상태(`showDistrictBadges`)에서는 매물/피드 **리스트 fetch 자체를 하지 않는다** (성능 목표). 시트에는 가이드만: "🔍 지도를 확대해 주변 매물을 봐요" + [📍 내 동네 보기] 버튼(기존 ◎ 현위치 로직 재사용 — 명시적이므로 원칙 OK). 헤더 "총 N건"(district-counts 합계)은 유지 — 규모감 제공.
2. **게이트 통과(충분 줌인)**: 현행 유지 — viewport bbox 자동 재검색(Airbnb식) + 리스트.
3. **뷰포트 기억**: 지도 이동/줌 시 마지막 뷰포트를 localStorage(`sgr.map.viewport`)에 저장, 재진입 시 복원. GPS 호출 없음.
4. 매물/피드 두 탭 동일 게이트.

## 비스코프

- 지도 초기 GPS 줌인(원칙 위반), 탭바/네비 변경, 배지 클러스터링 방식 변경, 서버 API 변경(bbox 파이프라인 기존 그대로).

## 레퍼런스 (Sonnet 리서치 260707 완료 — 요지)

- **당근·Chotot 모두 중고거래에는 지도 브라우징이 없다**(의도적 — 당근부동산·Nhà Tốt 등 부동산 버티컬에만 지도). 당근의 "동네 범위 4단계"가 줌을 대체하는 게이트. → 지도는 우리 차별 기능이므로 부동산류 패턴 준용이 맞음.
- **표준 게이트**(호갱노노·네이버부동산·직방): 도시 줌 = 집계(건수/평균)만 → 구~동 단위 줌인 시 개별 핀+리스트. 사용자 아이디어와 일치.
- 재검색: mapuipatterns 는 수동 "이 지역 검색" 버튼 권고이나, **현행 자동 bbox 재검색 유지 결정** — 이미 구현·QM 검증됐고 게이트가 fetch 자체를 막아 성능 문제 해소. 전환은 변경 폭 대비 이득 없음.
- 결과 상한: 업계 공통 고정치 없음. 현행 bbox size=50 캡 유지.
- 가이드 문구 톤: 중립·행동유도형 ("지도를 확대해 주변 매물을 봐요").
