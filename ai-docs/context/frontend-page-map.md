# 프론트엔드 페이지-메뉴-컴포넌트 맵

> **목적**: "동네지도에 어떤 기능개선이 필요해?" 처럼 **한글 메뉴명 기준**으로 질문받았을 때, 바로 해당 라우트·페이지 파일·핵심 컴포넌트를 찾아가기 위한 진입점 색인.
>
> **먼저 ADR부터 확인**: 대부분의 질문은 이 문서 전체를 읽지 않고도 `mcp__codebase-memory__manage_adr(mode: "get", project: "mnt-c-DEV-saigon_rider")` 압축 요약 한 번으로 답이 된다(메뉴 구조·SoT 위치·알려진 갭). 이 문서는 ADR에서 다루지 않는 **서브라우트/컴포넌트 세부 나열**이 필요할 때만 펼쳐 보는 상세 참조다. 메뉴/라우트 구조를 바꾸면 ADR과 이 문서를 함께 갱신한다.
>
> **이 문서 vs codebase-memory MCP**: 이 문서는 "메뉴명 → 코드 위치"의 **얕은 정적 지도**다. 실제 호출관계·데이터 흐름(어떤 API/스토어/네이티브 함수를 부르는지, 변경 시 영향 범위)은 매번 최신 상태로 바뀌므로 여기 박제하지 않는다. 아래에서 찾은 파일/컴포넌트명을 `codebase-memory` MCP(`project: mnt-c-DEV-saigon_rider`)의 `search_graph`/`trace_path`/`get_architecture`에 넣어 **살아있는 그래프**로 조회한다 (사용법은 문서 하단 [MCP로 더 깊이 파기](#mcp로-더-깊이-파기) 참조, 상세 도구 규칙은 [`agent-guidelines.md`](../agent-guidelines.md) §9).
>
> 라우트 정의 SoT: `frontend/src/App.tsx`. 한글 라벨 SoT: `frontend/src/locales/ko/translation.json`.
>
> **화면을 수정할 때 시각 규칙 SoT는 [`design-system.md`](design-system.md)** (2026-07-25 신설) — 아이콘(lucide 표준·이모지 판별 기준)·숫자(`.num`, `JetBrains Mono` 금지)·색 용법·표면 문법(`styles/system.module.css`)·상태 4종(`StateBlock`/`SkeletonRows`)·저사양 제약. 화면별로 문법을 새로 만들지 말고 이 문서를 따른다.

## 3. 메뉴별 상세

### 공통 위치 해석 정책 (2026-07-23)

- **Promise 파이프라인 SoT**: `lib/serviceLocation.ts`의 `requestDeviceLocation()` → `resolveServiceLocation()` → `resolveUsableLocation()` 체인. `native.ensureLocationPermission().then(native.getLocation)`으로 기기 좌표를 얻고, 서비스 영역 안이면 `{ coords, source: 'device' }`, 밖이면 `mapDefaults.ts`의 `BEN_THANH_FALLBACK`(`10.7716, 106.6980`)과 `{ source: 'fallback', reason: 'outside_service_area' }`를 **정상 resolve**한다. 권한·GPS·예상하지 못한 획득 실패는 이 체인에서 catch하지 않고 **reject**하며, Toast는 도메인 헬퍼가 아니라 각 화면에서 처리한다.
- **적용 CTA**: 동네지도 `[내 위치]`, 커뮤니티 `[내 동네]`, 마켓 `[내 현재 위치]`가 같은 해석 결과를 소비한다. 서비스 밖 안내 문구는 "서비스 지역 밖이에요 · 호치민 중심을 보여드려요"이고, 세 화면 모두 실제 범위 밖 좌표가 아니라 벤탄 fallback 좌표를 후속 동작에 사용한다.

### 공통 당겨서 새로고침(PTR) 패턴 — 전면 적용 (2026-07-27)

  - **철회**: 신규 status **`WITHDRAWN`** 을 `_VALID_STATUSES` 에 편입해 **기존 `/status` PATCH 를 재사용**(신규 엔드포인트 없음). `database/init/162_marketplace_listing_withdrawn_status.sql`(CHECK 제약 재정의, `bff_migrate` 등록됨). 피드·검색·상세 조회에서 완전 비노출, **영구**(재전이 400 `moderated`).
  - **⚠️ 철회 가능 조건 = 거래 무결성 보호**: 해당 매물에 `status='ACCEPTED'` 약속이 있으면 철회 불가(409 `active_appointment`) — 구매자가 먼저 약속을 취소해야 한다. 철회 시 약속 테이블에 쓰지 않으므로 `uq_mp_appointment_active_per_listing` 부분 유니크와 `_load_appointment` 의 `FOR UPDATE` 잠금 기반 무결성을 건드리지 않는다. **이 조건을 없애면 거래 무결성이 깨진다.**
- **검색 방식 전환 — 다국어 교차검색 (2026-08-01)**: 이전엔 마켓 검색이 **검색어를 3개국어로 번역해 원문 `title` 에 OR ILIKE** 하는 역방향 구조였다(`description` 미검색). 매 검색이 외부 번역 API 에 의존해, API 가 죽으면 검색 품질이 조용히 떨어졌다 — 실제로 Google Translate 가 3주간 403 이었는데 아무도 몰랐다. 대표 지적("영어로 올린 걸 한국 유저가 '자전거'로 검색하면 나와야 한다")을 실측 재현한 결과 `자전거`·`헬멧` 모두 **0건**이었다(해당 매물이 DB 에 존재하는데도).
  - 전환: 엔티티에 **`search_blob` 정규화 컬럼 + `pg_trgm` GIN**(`164_search_blob.sql`). 검색은 `COALESCE(search_blob,'') LIKE norm(q)` 조건 하나로 끝나고 **검색 경로에서 번역 API 호출이 사라졌다**. 정규화(`services/search_norm.py`)는 발음구별기호 제거·`đ→d`·소문자·공백압축을 **쓰기 시점 Python** 으로 수행한다
  - 사용자 체감 변화(라이브 실측): `mu bao hiem`(성조 없이) 0→**2건**, `xe may` 0→**1건**, 대소문자 무관. **베트남 사용자가 성조를 빼고 입력하는 실사용 패턴이 이제 매칭된다**

'미상'과 '안전'을 구분하지 못하며, `asyncio.gather` 19개 동시 호출이 레이트리밋에 걸리면 일부 구가 경고 없이 통째로 누락된다. **침수 경고가 빠지는 방향의 실패**라 기본값 선택이 잘못됐다(라이더 안전 직결 경로). 즉 이 항목의 '지도 뷰포트 기준 필터' 설계는 리스트에 대해서는 더 이상 유효하지 않다. **⚠ 정보 화면 4종의 위치 모델 비대칭(의도됨)**: 주유소·정비소·날씨 3화면은 기존 `LocationContextBar`/지역선택 피커를 그대로 유지하고, 침수만 이번 변경으로 지역선택이 없다. 침수지도는 도시 전역 위험 파악이 목적이라 ward 단위 선택이 오히려 방해된다는 판단이며, 나머지 3화면은 회귀 리스크를 줄이기 위해 무변경으로 남겨둔 결과다.
- **정보 지도 3종에 POI 참조 레이어 결선 (2026-07-31)**: 침수·주유소·정비소 지도에 랜드마크·공공시설 마커(POI)를 노출해달라는 대표 지시("복잡하게 하지 마라") — 이미 `NeighborhoodMapCanvas.tsx`에만 있던 `buildPoiLayer`(POI 조회결과→`MapMarkerV2[]` 변환, landmark/civic 뮤트색+아이콘)를 신규 공유 모듈 `components/maps/poiLayer.ts`로 이동하고 동네지도는 그 모듈을 import하도록 교체(중복 제거). 3화면 모두 `fetchPoiMapItems`(`api/poi.ts`, bbox 50%확장+1h TTL 캐시)로 조회 후 `markers={[...poiMarkers, ...기존마커]}`(POI가 배열 앞쪽=z-order 아래) 패턴으로 배선. bbox 소스만 화면마다 다르다 — 침수는 기존 `viewportBbox`(지도 팬/줌 결과) 그대로 재사용, 주유소·정비소는 `origin`+`FETCH_RADIUS_KM`(3km)로 매 렌더 계산. `SaigonMapV5.tsx`/`L3_ENABLED`는 무변경(POI 렌더 게이트는 `L2_VBW` 줌 임계치이지 L3 플래그가 아님). 마커 충돌 회피 로직은 만들지 않음(1차는 z-order만, 대표 지시대로 단순 유지) — 정비소 화면은 3km 반경 핀 100건대+POI 40여건이 겹쳐 혼잡할 수 있음(육안 확인됨, 개선은 후속 판단 대상).
  - **후속: L3 상세지도 활성화 + 진입 즉시 POI 노출 (2026-07-31)**: 위 1차 결선 이후에도 대표 지시("L3 상세지도 + POI가 곧바로 보여야") 미달 2건이 남아 있었다 — ① 3화면 모두 `lightweight`(리터럴 true)로 넘겨 depth3(건물/도로) 레이어가 항상 꺼져 있었음, ② `initialGps`가 `region ? {...} : undefined`라 지역 미선택("전체") 상태에선 도시 전체조망(D1, vb.w ≫ L2_VBW)으로 시작해 핀이 줌 게이트 아래 숨어 있었음. 조치: `lightweight={!L3_ENABLED}`로 `NeighborhoodMapCanvas.tsx`의 `childLightweight` 패턴 미러링(새 플래그 발명 안 함, `L3_ENABLED`는 SaigonMapV5.tsx 단일 소스), `initialGps`를 지역 선택 여부와 무관하게 `origin`(선택 동 centroid 또는 도시 기본 중심, 이미 데이터 조회에 쓰던 값)으로 항상 넘겨 마운트 즉시 `focusLatLng`가 L3 임계값(`L3_VBW*0.9`) 안쪽으로 줌인하도록 변경. 결과: 3화면 모두 진입 직후 건물/도로 상세 + POI 참조 레이어(공원/극장 등 랜드마크)가 확대 없이 함께 보임(Playwright 스크린샷 확인). **`forceMarkers` prop은 검토 후 채택 안 함** — L3 활성 시 자동으로 뷰포트가 이미 마커 게이트(`vb.w<L2_VBW`) 밑으로 들어가 불필요, 게다가 그 prop은 뷰포트 밖 마커의 컬링(`vb.x±50px` 바운드 체크)을 우회하지 못해 근본 해결이 아님. **⚠ 알려진 한계(구조적)**: L3 임계값 자체가 폭 ~1km 남짓(`L3_VBW≈700`유닛≈1.1km)이라, 주유소·정비소의 `FETCH_RADIUS_KM=3`(반경 3km, 지름 6km) 전체 도메인 핀이 초기 L3 뷰 안에 다 들어오진 않는다 — 사용자 위치 기준 가장 가까운 주유소/정비소가 500m 밖이면 진입 직후엔 도메인 핀 없이 POI(랜드마크)만 보이고, 팬/줌 아웃해야 나머지가 보임(2026-07-31 dev 계정 기준 재현: 가까운 주유소 0.7km→진입 시 0건, 정비소 0.4km→진입 시 일부 노출). `L3_VBW`를 넓히면 다른 모든 지도 화면(동네지도 포함)의 L3 발동 시점이 바뀌므로 최후수단 — 이번 작업 범위 밖으로 남겨두고 감독 판단 대기. **추가로 홈 진입 배선을 고쳤다**: 주유소·정비소는 `mapOpen = searchParams.get('view') === 'map'`(`InfoRepairList.tsx:36`, `InfoGasList.tsx` 동일)이라 쿼리가 없으면 지도가 아예 렌더되지 않는데, 홈 4지표 카드는 `infoNavQuery`(`WorldMapV2.tsx:267`, `?lat&lng`)만 붙여 navigate 하고 있어서 **대표가 카드를 눌러도 리스트만 나오고 L3/POI 작업이 보이지 않았다**. `WorldMapV2.tsx:520,527`의 두 링크에 `&view=map`을 추가해 지도로 직접 진입시킨다(날씨는 지도가 없고 침수는 지도가 화면 본체라 무변경). 이로써 위 225행 "주유소·정비소는 목록 우선" 정책이 홈 진입 경로에서는 더 이상 적용되지 않는다 — 화면 내 `지도/목록` 토글 칩은 그대로 유지. **⚠ 함정 2건(실제로 밟았음, 다음에 반복 금지)**: ① `initialGps` 를 넘기면 `SaigonMapV5.tsx:515` 가 `focusLatLng(..., { selectRegion: selectRegionOnLocate })` 를 호출하고, `focusLatLng` 내부는 `if (idx>=0 && selectRegion!==false){ setSelWard(idx); "리스트로 진입 → [지도] 누르면 push" 를 전제한 코드라, 홈 카드가 `&view=map` 으로 **지도 상태에 직접 진입**하게 되자 화면 안에 되돌아갈 목록 항목이 없어 뒤로가기가 홈으로 갔다. `navigate(-1)` 대신 `next.delete('view')` 로 쿼리를 직접 지운다(`InfoGasList.tsx`·`InfoRepairList.tsx` 동일). 목록에서 [지도]로 들어온 경우 `view=map` 이 여전히 push 로 쌓이므로 위 107행의 "Back 은 지도→목록 먼저 복귀" 의도는 유지된다 — 실측 확인(리스트 진입→지도→Back→리스트).

## MCP로 더 깊이 파기

이 문서에서 페이지/컴포넌트 파일을 찾은 뒤, 실제 호출관계·데이터 흐름·영향범위가 필요하면:

```
# 페이지 컴포넌트의 실제 호출관계(=연결된 API/store/native 함수) 확인
mcp__codebase-memory__trace_path(project="mnt-c-DEV-saigon_rider", function_name="NeighborhoodMap", direction="outbound", depth=2)

# 특정 컴포넌트/함수를 텍스트로 찾기
mcp__codebase-memory__search_graph(project="mnt-c-DEV-saigon_rider", query="SaigonMapV5")

# 이 파일을 누가 쓰는지(영향범위) 역방향 추적
mcp__codebase-memory__trace_path(project="mnt-c-DEV-saigon_rider", function_name="findWardAt", direction="inbound")
```

`trace_path(function_name="NeighborhoodMap", ...)`로 실제 조회하면 `fetchListings`/`fetchAds`(`api/market.ts`), `fetchFeed`(`api/feed.ts`), `fetchPoiMapItems`(`api/poi.ts`), `fetchBizMapItems`(`api/biz.ts`), `useLocationStore`/`useUserStore`, `native.ts`의 위치 권한 함수까지 한 번에 나온다 — "동네지도가 어떤 백엔드/상태와 엮여있나"를 코드 안 뒤지고 바로 확인 가능.

**주의**: 그래프는 워킹트리 전체(미추적 백업 파일 포함)를 인덱싱하므로, `_bak`/`bak2`/`v3bak` 등 접미사가 붙은 결과는 죽은 코드로 간주하고 무시한다. 코드 변경 후에는 [`agent-guidelines.md`](../agent-guidelines.md) §9 재인덱싱 규칙에 따라 `index_repository`로 갱신해야 이 문서와 그래프가 계속 일치한다.
