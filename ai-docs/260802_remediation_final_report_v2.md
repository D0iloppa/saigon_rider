## 2. v1 이후 추가로 해소한 것 (v1 에 없던 항목)

### 2.1 스키마 파리티 사고 — v1 의 검증 근거가 틀렸다

v1 §5.1 은 게이트 5(DB upgrade)를 **"fresh-init 165 SQL 전건 부트스트랩, ERROR 0건"** 으로 닫았다. **이 근거는 불충분했다.**

SQL 이 에러 없이 끝나는 것과 **결과 스키마가 라이브와 같은 것은 별개**다. 실제로 `users.deleted_at` 은 코드 10곳이 사용하는데 `database/init/` 어디에도 생성 구문이 없었다 — **신규 배포하면 로그인부터 깨지는 상태**였다. 반대 방향 드리프트(`badges.policy_id`)와 제약 불일치(`flood_confirmation.lat/lng` NOT NULL)도 있었다.

- 조치: `database/init/169_schema_parity_backfill.sql`(멱등), `bff_migrate` 의 `command`·`volumes` 양쪽 등록
- **검증 기준을 교체했다**: `fresh-init ERROR 0건` → **`라이브와 schema diff 0건`**
- 회귀 방지: `backend/app/tests/test_schema_parity.py`(DB 불필요, 정적 스캔)
- 재실측(2026-08-02): fresh-only **0건**, live-only 는 전부 Engine/Alembic 소유(고아 0건)

### 2.2 운영 서버 배포 (게이트 6: FAIL → 부분)

- 구 이력 `main@1012afd` → 새 `origin/main` 전환. 공통 조상이 없어 pull 불가 → 전체 백업(git bundle 445MB · DB 덤프 · 미추적 자산) 후 reset
- 대표의 미커밋 **랜딩 개편**(히어로 영상·파비콘·스토어 배지 제거)이 새 main 보다 최신이라 **3파일을 운영 버전으로 보존**
- **운영 DB 재생성**: 재생성 전 운영 DB 는 업체·POI·신고·광고통계 테이블이 통째로 없었다(**263컬럼 누락**, 112테이블). 실데이터는 42행(flood/fuel 참조)뿐이라 손실 없음
- 결과: 컨테이너 9종 healthy · `ready` **200**(db/redis/schema/engine) · bff 로그 ERROR **0건** · dev 와 스키마 **완전 일치**(1258컬럼, diff 0)
- **잔여**: 운영이 loopback 바인딩이라 **외부 도메인에서의 재검증**(strict CORS·보안헤더·OpenAPI/metrics 비공개) 미완 — 공개 도메인 처리 결정과 묶임

### 2.3 CI·E2E 도입 (게이트 8 의 "CI 미구성" 단서 해소)

- `.github/workflows/ci.yml` — 4 job + `pull_request` 한정 `e2e` job
- Playwright `frontend/e2e/` — `consent-gate` · `market-search` · `market-edit`
- E2E 가 **첫 실행에서 실제 결함을 잡았다**: dev 의 `saigon_frontend` 컨테이너가 소스보다 낡아 동의 게이트가 실제로는 동작하지 않고 있었다

### 2.4 운영 `.env` 키셋 (v1 B-7 확장)

v1 은 `SMS_PROVIDER_API_KEY` 하나만 지목했다. 실제로 대조해보니 운영 `.env` 에 **9개 키가 없었다.** CLAUDE.md 의 "`.env`/`.env.example` 키셋 동일" 규약이 **운영 `.env` 에는 한 번도 적용된 적이 없었다.**

- 가장 심각: `ZALO_API_PROXY` 부재 → 프록시 없이 한국 IP 에서 직접 호출 → Zalo 가 `error -501` 로 차단 → **운영에서 Zalo 로그인 실패**
- 조치: 9개 키 전부 생성, 대표가 값 2개(`ZALO_API_PROXY`·`GOOGLE_MAPS_API_KEY`) 입력 완료, bff 재기동 후 프록시 egress **VN** 확인
- `SMS_PROVIDER_API_KEY` 는 **값 있음** 확인 → v1 B-7 종결

### 2.5 탈퇴 계정 복구 + 탈퇴회원 해시 아카이브 (대표 지시, v1 범위 밖)

- **복구 플로우**: 탈퇴 후 재로그인이 `HTTP 404` 막다른 길이었다. 인증 성공 후 409 + 복구 토큰 → 사용자가 명시 확인해야만 복구. 회귀 금지 불변식 2가지를 테스트로 고정(토큰이 리다이렉트 URL 에 실리지 않음 / 복구 판정 지점 단일화)
- **익명화 UNIQUE 버그**: `del_<초단위 timestamp>` 는 `users.phone`/`nickname` 이 UNIQUE 라 같은 초에 두 명 탈퇴 시 **500**. `del_<uuid4>` 로 교체
- **해시 아카이브**(대표 결정: 식별자 해시만 1년): HMAC+pepper 필수(평문 SHA256 이면 전화번호는 전수 대입으로 즉시 역산), 탈퇴 시점 캡처, 복구 시 행 삭제, 1년 파기는 30일 파기와 별도 단계
- ⚠️ **개인정보처리방침 §4 개정 필요** — 현재 문안에 탈퇴회원 보관기간 명시가 없고 "식별정보 제거 형태 보관"으로만 돼 있다. 법무 검토 대상

### 2.6 기타

어드민 업체 직접 등록 + 사진 업로드 + CSV 대량 임포트 · 서비스 경계 안내(`market.outOfService*`) · 스플래시 [로그인] 중복 버튼 제거 · pre-commit `committed-secrets` 훅 신설
