# 파트너 라운지 IA/모바일 UX 개선 결과 (2026-09-09)

## 구현 완료

- 파트너 라운지 운영 탭의 전체 광고 카드 스택을 광고 개수·확인 필요 상태만 표시하는 단일 요약 진입 카드로 축소했다.
- `/biz/ads` 전용 광고 관리 화면을 추가하고 기존 소재 심사·계약·실제 노출 상태, 상세 이동, 계약 CTA eligibility를 그대로 이동했다.
- 광고 목록 → 광고 상세 → 뒤로가기 시 같은 가게의 `/biz/ads` 목록으로 복귀하도록 기존 history와 profile state를 보존했다.
- 성과 탭의 `최근 후기` 제목과 `미답변만` 필터를 같은 중심선에 놓고 필터 폭을 intrinsic으로 고정했다.
- 내 소식·가격표·광고 관리 hero를 설명 위/CTA 아래의 세로 흐름으로 바꾸고 모바일 CTA를 한 행 전체 폭으로 통일했다. 설명 폭은 260px 제한 대신 가용 모바일 폭을 쓰되 34rem으로 제한했다.
- 세 관리 화면에 검색·정렬·검색 결과 0건·초기화 UX를 추가했다. 검색 범위는 API가 제공한 현재 목록으로 정확히 표시한다.
- 소식은 기본 최신순/오래된순과 작성 시각을 제공한다. 검색 결과가 0건이어도 다음 서버 페이지가 있으면 `더 보기`를 유지하고, 추가 페이지는 ID로 중복 제거한다.
- 가격표는 기존 `sortOrder`를 기본값으로 보존하고 이름순/낮은 가격순과 등록 시각을 제공한다.
- 광고는 확인 필요 우선순위를 기본값으로 보존하고 최신순/오래된순과 등록 시각을 제공한다. 상세를 주 행동, 계약 안내를 보조 행동으로 분리했다.
- 소식 카드에서는 `미리보기·수정`을 주 행동으로, 삭제를 분리된 위험 행동으로 배치했다. 검색·정렬·카드 행동의 터치 영역은 최소 44px이다.
- ko/en/vi의 모든 신규 관리 문구를 함께 추가했다.

## 관리 화면 인벤토리와 API 경계

- 내 광고 `/biz/ads`: 광고 배열 API는 페이지·전체 개수·검색 파라미터가 없다. 따라서 현재 응답 안에서만 검색·정렬하며 전체 개수라고 표현하지 않는다.
- 내 소식 `/biz/news`: API는 `created_at` 내림차순 offset/limit(화면 20개)만 제공하고 검색·정렬·전체 개수·`updated_at`은 없다. 작성 시각만 표시하며 수정 시각을 추측하지 않는다.
- 가격표 `/biz/prices`: API는 `createdAt`, `sortOrder`를 제공하지만 검색·정렬 파라미터와 수정 시각은 없다. 현재 응답 범위에서만 검색·정렬한다.
- 매물 등록 `/biz/listings/new`: 단일 `MarketCreate` 작성 흐름이며 파트너 소유 매물 관리 목록/API가 없다. 검색·정렬·관리 카드 패턴을 억지로 적용하지 않았고, 별도 관리 화면은 후속 제품/API 과제로 남긴다.
- 후기 관리: 별도 라우트가 아니라 성과 탭에 포함된다. 서버 페이지네이션, 최신순, 미답변 필터, 작성 시각, 답글 수정·삭제·신고가 이미 있어 이번에는 헤더 정렬 개선만 유지했다.
- 사업자 검증: 단일 제출/상태 확인 흐름이므로 목록 검색·정렬 패턴 적용 대상이 아니다.

## 실패·미실행 구분

- 첫 브라우저 시도는 task 폴더 기준 `playwright` 패키지 해석 실패로 코드 진입 전 종료했고, frontend의 기존 설치 경로를 명시해 해결했다.
- 다음 시도의 목표 광고 여정은 통과했으나 범위 밖 초기 홈 API를 의도적으로 차단해 생긴 console noise 때문에 harness assertion이 실패했다. 목표 API만 판정하도록 범위를 좁혔다.
- 마지막 시도는 ko-KR 390px 광고 여정과 캡처까지 성공한 뒤, 소식/가격표 hero 선택자가 앱의 숨겨진 알림용 `<section>`을 먼저 잡아 timeout으로 종료했다. UI 자체 실패가 아니라 harness 선택자 실패다.
- 요청에 따라 테스트 인프라 수정을 중단했다. 따라서 다음은 브라우저 미검증으로 남는다:
  - 소식·가격표·광고의 신규 검색/정렬/카드 행동 및 hero의 390/430px rendered geometry
  - en/vi 브라우저 렌더
  - 성과 탭 후기 제목/필터의 rendered center 좌표
- 기존 미검증 `frontend/src/pages/biz/bizManageUi.e2e.mjs`는 근거로 사용하지 않았다.
