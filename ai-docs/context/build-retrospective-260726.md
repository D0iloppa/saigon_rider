# 이렇게 만든 게 맞았나 — 구현 회고 (2026-07-26)

> **작성 맥락**: [`../spec/service-concept-260726.md`](../spec/service-concept-260726.md) 서비스 구상서를 기준선으로 삼아, **지금까지의 구현이 그 서비스를 만드는 데 맞는 배분이었는지** 되짚은 문서. 실제 구현은 AI(본 어시스턴트 계보)가 수행했으므로 이 문서는 **자기 회고**다. 대표 요청에 따라 **변명도 함께, 성립/불성립 판정을 붙여** 남긴다.
>
> **성격**: 비난 문서가 아니다. 코드를 지우기 위한 근거도 아니다. **다음 배분을 바꾸기 위한** 문서다.

---

## 1. 판정 요약

**아니다. 배분이 틀렸다.**

기술적 품질(불변식·보안·i18n·성능 제약 준수)은 대체로 좋고, 개별 결정도 상당수 합리적이었다. 그런데 **자원이 서비스의 핵심 루프가 아닌 곳에 쏠렸고, 결과적으로 이 서비스의 유일한 차별점은 한 줄도 구현되지 않았으며, 만든 것 중 상당량은 아직 아무도 화면으로 본 적이 없다.**

한 문장으로: **잘 만들었지만, 잘못된 것을 잘 만들었다.**

공정하게 적는다. 이건 잘한 것이고, 되돌릴 이유가 없다.

## 4. 틀렸던 결정 (심각도 순)

### 4-1. Engine 17,072줄 — 피벗 후에도 아키텍처의 하중 구조로 남았다

게이미피케이션 RPG 경제(가챠·상점·시즌패스·스킬트리)를 **별도 서비스로** 구축했다. 2026-07-06 피벗으로 이 도메인 전체가 휴면이 됐다. 그런데 Engine은 여전히:
- Docker Compose 서비스로 기동되고 헬스체크를 받고
- BFF가 `engine_client.py`로 HTTP 연동을 유지하고
- "BFF는 Engine DB에 직접 접근 금지"라는 **불변식이 아직 코드베이스 전체를 제약하고**
- 문서·ADR·리팩터에서 계속 지분을 차지한다

**보존 결정 자체는 합리적이다(§3). 문제는 애초에 이 규모로 만든 것이다.** 중고거래 서비스에 17,000줄 규모의 별도 보상 엔진이 선행 투자로 필요했던 근거가 없다.

### 4-2. 차별점을 마지막까지 손대지 않았다 — 그리고 전제 조건도 방치했다

거래 라이프사이클 7단계 중 ④합의~⑤이동만 비어 있다. 이게 서비스의 유일한 구조적 차별점이다. 그 사이에 만든 것: T&S 전체, 관리자 콘솔 리메이크, 광고 성과 대시보드(CPM/CPC/CPA), 랜딩 3도메인, 디자인 전면 정비 143파일.

더 나쁜 것은 **전제 조건인 `GOOGLE_MAPS_API_KEY`가 발급되지 않은 채로 몇 주가 지났다는 점이다.** 경로·ETA 코드는 완료해두고 "휴면"으로 적어둔 뒤, 그 키가 차별점을 막고 있다는 사실을 **차단요소로 격상해 매번 올리지 않았다.** 발급은 대표 권한이지만, **막힌 걸 계속 시야에 올려두는 건 내 일이었다.**

### 4-3. 배포하지 않았다 — 그래서 만든 것을 아무도 못 봤다

`current.md`에 반복되는 문장: `워킹트리 미커밋` / `운영 미배포` / `실기기 미검증` / `실화면 확인 불가`.

정점은 07-24~25다. **디자인 전면 정비 143파일 + 지도 5화면 재설계를 완료했고, 그 개선된 화면을 본 사람이 아무도 없다.** 정적 검증(tsc·ESLint·키 패리티·계약 테스트)은 통과했지만, 정적 검증은 "디자인이 나아졌는지"를 알려주지 않는다.

이건 단순 절차 누락이 아니다. **피드백 루프가 끊긴 상태로 대량 생산을 계속한 것**이고, 그래서 다음 항목이 발생했다.

### 4-4. 같은 화면을 한 달에 8번 다시 만들었다

동네지도 기준으로 2026년 7월: 07-07(줌 게이트·시나리오 회귀) → 07-10(업체 핀 P1) → 07-11(3패키지) → 07-12(업체 UX 4패키지 → 구조 리팩토링 → 2차 배치, **같은 날 3회**) → 07-24(목록 우선 통개편) → 07-25(재설계). 마지막 두 번은 **직전 결과물이 "디자인이 구리다"는 지적을 받아서** 다시 만든 것이다.

원인은 실력이 아니라 **기준선 부재**다. "이 앱의 중심 축이 무엇인가"가 정해지지 않은 상태에서 화면을 만들면, 만들 때마다 다른 답이 나온다. 07-24에 지도를 첫 화면에서 걷어냈더니 마켓 탭과 중복되는 문제가 드러난 것이 그 증거다 — **애초에 축이 정해져 있었으면 발생하지 않는 문제였다.**

### 4-5. 가짜 UI를 만들어서 코드에 넣었다

07-25 정비 중 발견된 것들이고, **전부 이전 세션의 내가 만든 것이다.**

- `InfoRepairDetail`: 사진이 없는데 슬라이드 인디케이터 `1 / 3` 표시. 동작 없는 하트. **전화·경로·공유 3버튼이 onClick 없는 죽은 버튼**
- 주유소 `전화` 버튼도 동작 없음
- `JetBrains Mono`를 7개 파일에서 지정 — **index.html에 로드되지 않는 유령 폰트.** 한 달간 쿠리어체로 렌더 중
- `RideNav.tsx`가 CSS Module 스코프 밖 전역 클래스 참조 → 폰트 지정 자체가 미적용
- 유령 CSS 토큰 다수(`--border`·`--text-primary`·`--shadow-sm`…) → 좋아요 활성색·입력 보더색 미적용
- `GasStationSheet` 다크모드 `background: white` 하드코딩
- **조회 실패를 "비어 있음"으로 위장 5곳** / 로드 실패 시 스켈레톤 무한 회전 / 실패 시 "불러오는 중…" 영구 표시
- 의미 없는 `🥇1위` 배지

**"정직한 표기" 원칙(CLAUDE.md)은 이걸 다 만든 다음에 발견하고 나서 쓰였다.** 원칙이 예방이 아니라 사후 수습이었다.

### 4-6. 자체 벡터맵에 과투자한 뒤 강등시켰다

`SaigonMapV5`에 도로 케이싱 2-pass, 줌 연동 도로폭 지수곡선, 4단 명도 위계 팔레트, 건물 음영 duplicate, round cap/join까지 넣었다. **그 다음 07-24에 지도를 첫 화면에서 걷어내고 명시적 진입 시 lazy load로 강등했다.**

자체 렌더 선택 자체는 근거가 있다(§3). 그런데 **건물 음영과 도로 케이싱은 중고거래 사용자의 문제를 하나도 풀지 않는다.** 같은 시간을 ⑤이동 단계에 썼으면 차별점이 나왔다.

부수 결과: 회귀 하네스가 WSL 전용(`playwright-core` 미설치 + Linux chromium 경로 + `localhost:18090` 하드코딩)이라 **Windows에서 지도 자동 회귀를 못 돌린다.** 검증 자산을 만들면서 실행 환경을 확인하지 않았다.

### 4-7. 관리자 콘솔을 두 벌 유지하고 있다

레거시 Jinja 콘솔(`admin_legacy.py` 4,524줄, 24메뉴) + 신규 React SPA. 신규 SPA로 **2차 이식이 안 끝난 메뉴가 20개 이상**(퀘스트·피드·SRE 6메뉴·제보 심사 3종·비즈 심사 2종·푸시·POI…). 게다가 신규 SPA는 만든 뒤 "화면단 재설계"를 또 한 번 했다.

관리자 도구는 **내부 사용자 1~2명**을 위한 것이다. 사용자 0명인 서비스에서 관리 콘솔을 두 벌 유지하는 건 배분 오류다.

### 4-8. 광고주 0인 상태에서 광고 성과 대시보드를 만들고 있다

**지금 이 순간 워킹트리에서 하고 있는 작업이다.** 노출(viewability)·클릭·CTA 전환·CPM/CPC/CPA·일별 롤업·빈 상태 7종.

계약 광고주는 0명이고 확보 경로도 미정이다. **광고주가 없으면 이 대시보드를 열어볼 사람이 없다.** 지역 광고는 전국 트래픽이 아니라 한 개 구의 밀도가 상품이므로, 필요한 것은 대시보드가 아니라 가게 10곳이다.

### 4-9. 제품 정의 문서가 오늘 처음 생겼다

이 프로젝트의 정체성 문서(`service-concept-260726.md`)는 **2026-07-26에 처음 작성됐다.** 그전까지 정체성 SoT는 피벗 전 게임앱 스펙(`overview.md`, 27화면)이었고, 그걸 읽은 사람은 서비스를 오해하게 되어 있었다.

ADR도 오늘 처음 저장됐다. `current.md`에는 `ADR 저장 미완`이 2026-07-10부터 **최소 5개 세션에 걸쳐** 반복 기록돼 있다. MCP 연결 끊김이 원인으로 적혀 있지만, **md 파일로 남길 수는 있었다.**

### 4-10. 밀지 않았다 (가장 근본적인 실패)

CLAUDE.md 제1원칙은 이렇게 적혀 있다:

> 더 단순한 길이 있으면 **반박**한다. 필요할 땐 push back.

`current.md`에 기록된 지시들 — *"디자인 최고가 될 수 있도록 부족한 부분 다 작업해"*, *"전체 작업 다 진행해"*(도달 불가 화면 포함) — 에 대해 나는 그대로 실행했다. **도달 불가 화면(`SkillTree`)까지 디자인을 정비했다.**

그 자리에서 해야 했던 말: *"도달 불가 화면과 휴면 도메인을 정비하는 건 지금 배분상 손해입니다. 대신 이 시간에 ④합의~⑤이동을 만들면 차별점이 생깁니다."*

**규칙을 지키지 않은 게 아니라, 규칙이 정확히 이 상황을 위해 쓰여 있는데 발동하지 않았다.**

## 6. 근본 원인 하나

위의 10개는 대부분 **하나의 원인의 증상**이다.

> **"무엇을 만드는 서비스인가"가 문서로 없었다.**

그래서:
- 축이 없으니 화면을 만들 때마다 다른 답이 나왔다 (§4-4)
- 우선순위 기준이 없으니 눈앞에 있는 것(T&S·admin·광고·디자인)을 만들었다 (§4-7, 4-8)
- 무엇이 코어인지 모르니 코어(14.2%)보다 휴면(21.3%)에 더 썼다 (§2)
- 차별점이 무엇인지 명시돼 있지 않으니 그게 0줄인 걸 아무도 이상하게 여기지 않았다 (§4-2)

**그 문서가 오늘 생겼다.** 즉 오늘까지의 배분 오류는 이해 가능하고, **오늘 이후의 배분 오류는 이해 불가능하다.**

## 7. 다시 만든다면 (그리고 지금부터 적용할 순서)

```
1. 서비스 정의 1장            ← 실제로는 3개월 뒤에 나왔다
2. 거래 루프 한 바퀴만        발견 → 문의 → 합의 → 만남 → 완료
                              (지도 없음, 게임 없음, admin은 SQL로 대체)
3. 배포하고 내가 본다         한 개 구, 실제 매물 10건
4. 차별점 하나만              🛵 N분 + 만남 장소 제안
5. 유저 20명에게 쓰게 한다    가정 검증: 진짜 문제가 "만남의 마찰"인가?
6. 그 다음에 신뢰/T&S/admin/광고/디자인 시스템
```

핵심은 순서다. **2~5는 지금 있는 코드의 14.2%로 할 수 있었던 일이고, 나머지 85.8%는 5번 이후에 해도 됐다.**

## 8. 재발 방지 — 운영 규칙에 넣을 것

§5-10(세션 컨텍스트 초기화)이 구조적 원인이므로, **개인의 각오가 아니라 절차로** 막아야 한다.

1. **배분 측정을 정례화한다.** 도메인별 코드 규모 × "코어/지원/휴면/수익" 태그를 월 1회 측정해 `current.md`에 남긴다. §2 표가 한 번도 없었다는 게 문제였다.
2. **"차별점 진척"을 모든 보고의 고정 항목으로 둔다.** 이번 주에 차별점이 0줄이었으면 그 사실을 매번 쓴다.
3. **미배포 작업물의 상한을 둔다.** 배포·확인 없이 다음 대량 작업을 시작하지 않는다. 143파일 미확인 같은 상태를 만들지 않는다.
4. **"이 작업은 누가 쓰나"를 착수 전에 한 줄로 답한다.** 답이 "사용자 0명" 또는 "광고주 0명"이면 착수 전에 보고한다.
5. **반박은 선택이 아니라 산출물이다.** 대량 작업 지시를 받으면 **실행 전에 "더 싼 대안 1개"를 반드시 제시**한다. 그러고도 지시가 유지되면 그때 전량 실행한다(그건 대표의 결정이다).

## 9. 한 줄 결론

**기술은 신뢰할 만하고 배분은 신뢰할 수 없었다.** 코드 21,081줄 중 서비스의 존재 이유에 해당하는 것은 14.2%이고 차별점은 0%다. 문제는 실력이 아니라 **무엇을 만드는지 정하지 않은 채 3개월을 잘 만든 것**이며, 그 정의가 오늘 생겼으므로 오늘부터는 같은 변명을 쓸 수 없다.
