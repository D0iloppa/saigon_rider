# 업체 등록 알바 — 물품 등록 동행 포함 단가 재산정

> **작성일** 2026-08-10 · 내부 보고용
> **개정 대상** `업체 등록 알바 — 단가 제안.pdf` (2026-08-06, 가입만 / 10건 30만동 — 리포 밖 파일)
> **변경 전제** 알바가 **업체 가입에 더해 그 가게의 물품(매물) 등록까지 동행**한다
> **관련** [`260810_service_usability_diagnosis.md`](../260810_service_usability_diagnosis.md) 부록 A(초기 매물 0 해법) — 이 작업이 A-2(b)의 실행안이다

## 0. 결론

**기본급 300,000동은 유지하고, 할당 구성을 `가입 10건` → `가입 8건 + 매물 12건`으로 바꾼다.**
작업 시간은 6.1시간으로 기존과 같고, 예산은 **4.6% 증가**하는 대신 **매물 384건**이 함께 생긴다.

| | 기존안 (가입만) | **재산정안 (가입+매물)** |
|---|---|---|
| 기본 할당 | 가입 10건 | **가입 8건 + 매물 12건** |
| 기본 일급 | 300,000동 | **300,000동 (동일)** |
| 초과 인센티브 | 가입 건당 30,000동 | 가입 건당 30,000동 · **매물 건당 7,000동** |
| 총 예산(8영업일·4명) | 14,900,000동 | **15,582,500동 (+4.6%)** |
| 산출물 | 업체 320곳 | **업체 256곳 + 매물 384건** |

**핵심은 "돈을 더 써서 매물을 산다"가 아니다.** 가입 할당을 10→8로 낮춰 확보한 시간에 매물을 올리는 것이므로,
같은 인일(person-day)로 결과물의 종류가 하나 늘어난다. 매물 384건은
[사용성 진단 부록 A-6]의 임계 밀도 목표(파일럿 구 활성 매물 150건)를 **2.5배 초과**한다.

## 1. ⚠️ 선행 결정 — 지금 코드로는 이 계획이 반쪽이다

**이 절을 먼저 결정하지 않으면 알바를 투입해도 의도한 결과가 나오지 않는다.** 코드 실측 3건:

### (1) 업체 계정은 매물을 올릴 수 없다
업체(파트너) 도메인은 신청·검증·관리·소식·광고까지 있지만 **매물 등록 경로가 없다**
(`backend/app/routers/biz.py` — 판매자 연결 없음). 매물의 판매자는 개인 사용자다.

### (2) 매물 등록에는 SMS OTP 인증이 서버에서 강제된다
프론트 가드(`VerifiedSellerRoute`)뿐 아니라 **서버가 403으로 막는다**:
`backend/app/routers/market.py:541-544` — `seller.phone_verified_at is None`이면
`"Phone verification required to list items"`. 우회 불가.

> 현장에서 이것이 의미하는 것: 사장 폰으로 **전화번호 입력 → SpeedSMS 수신 대기 → 6자리 입력**을 해야 한다.
> 가게 안에서 SMS가 안 오면 그 업체의 매물은 **0건**이 된다.

### (3) 업체 프로필과 매물이 서로 연결되지 않는다
가입시킨 업체 페이지(`/biz/:id`)에 그 가게의 매물이 붙지 않고, 매물 상세의 판매자는 개인으로 표시된다.
**"가게를 등록시켰는데 가게 페이지에 파는 물건이 없다."**

### 선택지

| 옵션 | 내용 | 현장 영향 | 개발 |
|---|---|---|---|
| **1 (권장)** | 업체 계정에 매물 등록 권한 부여 — **사업자 검증을 OTP 대체 인증으로 사용** | OTP 단계 소멸(하루 28분 절약), 업체↔매물 연결됨 | 필요 (BFF 권한 + 프론트 진입점) |
| **2** | 현재 코드로 강행 — 사장 개인 계정 + SMS OTP | 업체당 +3.5분, SMS 실패 시 매물 0건, 업체↔매물 미연결 | 없음 |
| **3** | 운영 대행 계정으로 등록 + "위탁 등록" 표기 | 사장 참여 불필요(빠름), 그러나 주인 없는 데이터 | 어드민 등록 화면 필요 |

**본 문서의 금액은 옵션 2(현재 코드) 기준으로 산정했다** — 개발 없이 바로 투입 가능한 보수적 안이기 때문이다.
옵션 1을 먼저 개발하면 같은 예산으로 **매물이 하루 4건씩 더** 나온다(§6 비교).

## 2. "1건"의 재정의 — 무엇을 하면 인정하는가

기존 5단계에 **6~7단계를 추가**한다. 가입과 매물은 **별개 카운트**다.

### A. 가입 1건 (기존과 동일)
1. 담당 구역 가게 방문 → 베트남어 안내지 제시
2. 무료 등록 설명, QR 스캔으로 앱 진입
3. 사장 Zalo 로그인 → 파트너 신청 작성 동행 (필수: 상호명·주소/지도 핀 — `biz.py:163-166`)
4. 제출 완료 화면 + 간판 사진 촬영
5. 당일 명단 제출 → 내부 검수 승인

### B. 매물 1건 (신규)
6. **사장 전화번호 인증 동행** (업체당 1회 — SMS OTP. 옵션 1 채택 시 생략)
7. **매물 등록 동행** — 아래 5개를 모두 채워야 1건:
   - 실물 사진 **2장 이상** (서버 필수: 최소 1장 — `MarketCreate.tsx:100`)
   - 제목 (베트남어)
   - 가격 (0동 = 나눔이므로 **업체 매물은 0원 금지**)
   - 카테고리 지정
   - 거래 희망 장소 = 가게 위치

> **가입 없이 매물만, 매물 없이 가입만도 각각 인정된다.** 물건을 팔지 않는 업종(세차·정비 서비스)은
> 가입만 카운트한다 — 억지로 매물을 만들게 하면 §5의 쓰레기 매물 문제가 생긴다.

## 3. 소요 시간 재산정

원본 실측(12~18분/성공)에 신규 단계를 더한 값이다.

| 단계 | 소요 | 비고 |
|---|---|---|
| 진입·대기·안내지 | 2~4분 | 기존 |
| 무료 설명 + QR 진입 | 2~3분 | 기존 |
| Zalo 로그인 → 파트너 신청 | 6~10분 | 기존 |
| 제출 확인 + 인증샷 | 1~2분 | 기존 |
| **전화 인증(OTP 수신 대기)** | **2~5분** | **신규 · 업체당 1회 · 옵션 1이면 0** |
| **매물 1건차** (사진 촬영 포함) | **4~6분** | **신규** |
| **매물 2건차 이후** | **3~4분** | **신규 · 사진만 새로 찍고 폼 재사용** |
| 거절 1건 | 3~5분 | 기존 |

### 하루(6~7시간) 배분 검증 — 전환율 25% 가정

| 항목 | 계산 | 소요 |
|---|---|---|
| 가입 성공 8곳 | 8 × 15분 | 120분 |
| 전화 인증 8회 | 8 × 3.5분 | 28분 |
| 매물 12건 (4곳은 2건, 4곳은 1건) | 4×8.5 + 4×5 | 54분 |
| 거절 24곳 | 24 × 4분 | 96분 |
| 이동 32방문 | 32 × 2.2분 | 70분 |
| **합계** | | **368분 = 6.1시간** |

기존안(290분 + 이동 = 6~7시간)과 **같은 노동 강도**다. 가입 2건을 줄여 만든 시간이 매물 12건으로 바뀐 것이다.

> **추정치 경고**: 전환율 25%는 원본과 동일하게 콜드 방문 영업의 일반 범위에서 잡은 값이고 현지 실측이 없다.
> 매물 등록 소요(3~6분)도 코드상 입력 항목에서 역산한 값이다. **파일럿 1일로 둘 다 실측해야 한다.**

## 4. 단가 — 기본급은 그대로, 할당 구성만 바꾼다

| 구분 | 금액 | 조건 |
|---|---|---|
| **기본 할당 달성** | **300,000동** | **가입 8건 + 매물 12건** |
| 가입 초과 | 건당 30,000동 | 9건째부터 |
| **매물 초과** | **건당 7,000동** | **13건째부터 · 일 25건 상한** |
| 가입 미달 | 건당 25,000동 | 최저 180,000동 보장 |
| **매물 미달** | **건당 6,000동** | 위 최저 보장에 합산 |
| 유류·데이터 수당 | 50,000동/일 | 전원 별도 |
| 현장 반장 수당 | +100,000동/일 | 4명 중 1명 |

**목표 달성 시 실수령 350,000동/일** — 기존안과 동일하다.
좋은 날(가입 10 + 매물 16)이면 `300,000 + 2×30,000 + 4×7,000 = 388,000` + 유류 = **438,000동**.

### 지급 시뮬레이션

| 실적 | 지급액 | 비고 |
|---|---|---|
| 가입 5 + 매물 4 | 180,000 | 최저 보장 (125,000+24,000 → 보장선 적용) |
| 가입 7 + 매물 9 | 229,000 | 175,000 + 54,000 |
| **가입 8 + 매물 12** | **300,000** | **← 목표선** |
| 가입 9 + 매물 14 | 344,000 | 300,000 + 30,000 + 2×7,000 |
| 가입 10 + 매물 16 | 388,000 | |

가입 7→8 + 매물 11→12 구간에서 **71,000동이 점프한다.** 기존안의 설계 의도(마지막 1건을 채우게 만드는 압력)를 유지했다.
최저 보장 180,000동은 법정 최저선(호치민 1지역 25,500동/시 × 7시간 = 178,500동, 제293/2025/ND-CP)이며 변경 없다.

### 매물 단가 7,000동의 근거
기본급 환산 시급 42,857동(300,000 ÷ 7시간) 기준 3.5분 = 2,500동.
성과급 프리미엄과 **사진 촬영·베트남어 입력·품질 책임**을 반영해 약 2.8배인 7,000동으로 잡았다.
가입 1건(30,000동, 15분 = 분당 2,000동)과 매물 1건(7,000동, 3.5분 = 분당 2,000동)의 **분당 단가가 같다** — 어느 쪽도 유리하지 않게 설계했다.

## 5. 🔴 신규 리스크 — 건당 지급은 쓰레기 매물을 부른다

가입은 사장이 직접 하므로 위조가 어렵지만(원본 §6 판정), **매물은 알바가 대신 입력할 수 있다.**
건당 7,000동이 걸리면 인터넷 사진을 퍼오거나 같은 물건을 반복 등록할 유인이 생긴다.
**이것이 이번 범위 확장에서 가장 큰 신규 위험이다.**

### 검수 기준 (미달 시 해당 건 미인정)

| # | 기준 | 확인 방법 |
|---|---|---|
| 1 | 실물 촬영 사진 2장 이상 — 스톡·인터넷 이미지 금지 | 배경에 가게가 보이는지 육안 검수 |
| 2 | 같은 가게에서 동일 물품 중복 등록 금지 | 제목·사진 중복 확인 |
| 3 | 가격 0동(나눔) 금지 | 업체 매물이므로 |
| 4 | 카테고리 지정 필수 | 미지정 시 노출이 떨어진다 |
| 5 | 거래 장소 = 실제 가게 위치 | 파트너 신청의 핀과 대조 |
| 6 | **업체당 정산 상한 5건** | 한 가게에서 무한 등록 방지 |

**반복 위반 시 계약 해지.** 이 기준을 SOP와 계약서에 명시하고, 첫날 파일럿에서 실제로 한 건 반려해 보여야 한다.

### 사후 정리 부담
사장이 관리하지 않는 매물이 쌓이면 "판매 완료됐는데 계속 올라와 있는" 상태가 된다.
**등록 후 30일 시점에 업체에 확인 메시지를 보내는 운영 루틴**을 잡아둘 것.

개발 공수가 2~3일 이내라면 이쪽이 유리하다.

기존 7종(안내지·QR·구역지도·SOP·정산표·반장 Zalo 그룹·유류수당)에 **4종을 추가**한다.

## 8. 리스크 (신규 3건 추가)
