## §0. 한 장 요약

**상용 가부: 파일럿(1개 구 한정) GO / 전면 상용 NO-GO** — 감사 판정(000_SYNTHESIS §1) 유지. 이 문서는 그 두 문턱을 각각 정의하고(§1), 문턱을 넘는 데 필요한 구현 리스트를 확정한다(§5).

**병목은 기능이 아니라 3개 시스템 층이다** (000_SYNTHESIS §1):
1. **계측 0** — 무엇이 되고 안 되는지 판정할 수단 자체가 없다. 파일럿의 목적이 "배우는 것"인데 배울 도구가 없으면 파일럿도 무의미하다. → **최우선.**
2. **신뢰 판단 규칙 0** — 도구(신고·제재·모더레이션)는 완성, 정책(자동 신호·우선순위·통보·구제)이 0.
3. **수익 파이프라인 가운데 끊김** — 광고를 팔 수는 있으나 효과를 증명 못 해 재구매 논리가 없다. 수익이 광고 단일 의존이므로 매출 전체가 여기 걸린다.

**최종 구현 리스트: 15건** (§5) — 파일럿 문턱 10건(선행: S 4건 → 계측 2건 → 신뢰 3건 → 노출 재개 1건), 전면 문턱 5건. W0 9커밋은 완료로 별도 표기.

**대표가 먼저 결정해야 가장 많이 풀리는 것** (§8): **D-18(퍼널 계측 방식)** 과 **D-19(surface 값 카탈로그)** — 이 둘이 계측 2건(리스트 최대 항목)을 막고 있고, 계측이 다시 광고 재개(D-2)와 전면 판정 전체를 막는다.

**코드로 안 되는 것** (§7): 실매물 공급(운영·영업), 베트남 법규 확인(법무), 운영 인력 배치, 실기기 RC 검증. 이 넷은 구현 리스트와 무관하게 병행돼야 한다 — 특히 공급 0(213건 중 188건 단일 계정)은 어떤 코드로도 못 푼다.

## §1. "상용 서비스 수준"의 정의

판단: "완벽"이 아니라 **최소 상용 문턱**을 정의한다. 기준은 카파시 #4 — 전부 검증 가능한 문장이어야 한다.

### 1-1. 파일럿 문턱 (1개 구 한정 공개)

파일럿의 목적은 **"이 동네에서 거래가 실제로 일어나는가"를 측정으로 배우는 것**이다. 따라서 파일럿 문턱의 핵심은 완성도가 아니라 **폐루프(사용자 행동이 시스템 응답으로 되돌아옴)와 관측 가능성**이다.

| 관점 | 파일럿 문턱 조건 (검증 가능형) | 현재 |
|---|---|---|
| 사용자(구매자) | 비로그인 열람→가입→문의→약속→완료 루프가 실기기에서 끊김 없이 수행되고, 각 단계 도달이 이벤트 테이블에 기록된다 | 루프 코드는 이어짐(002_personas §1) / 계측 0 (B-31) |
| 판매자 | 등록→노출→문의응대→완료→후기까지 자력 수행. 매물이 숨김·삭제되면 **사유 통보 + 이의 경로(티켓)가 끝까지 열려 있다**(답변 열람 포함) | 통보 있음(002_trust B-5) / 이의는 절반(D-22) |
| 업체 | 광고 노출이 실제 지면에서 켜져 있고, 노출·클릭 수가 익일 BizDashboard 에 0 아닌 숫자로 표시된다 | 노출 전면 OFF + 계측 파이프라인 0 (002_ads §B·C) |
| 운영자 | ① 신고 접수→우선순위 큐→처리→**신고자·피신고자 양측 통보** 폐루프 ② 주간 GMV·퍼널 숫자를 어드민에서 산출 가능 ③ 신고 적체 시 경보 | 신고자 통보 0건(002_trust B-4), 우선순위·경보 0(B-2·B-9), GMV 집계는 됐으나 원본 커버리지 1/21 |

**+ 운영 조건(코드 밖)**: 파일럿 구 안에 실사용자 활성 매물이 유의미하게 존재(목표치는 대표·영업이 설정 — "확인 필요", §7-1). 매물 0인 동네를 여는 것은 측정 대상이 없는 실험이다.

### 1-2. 전면 상용 문턱

전면 공개는 **파일럿 데이터로 판정**한다 — 지금 수치를 못 박는 것은 근거 없는 소원이 된다.

| 축 | 전면 문턱 조건 |
|---|---|
| 성장 | 파일럿 계측 데이터에서 핵심 전환(예: 신규 매물→7일 내 첫 문의율)이 대표가 설정한 기준선을 통과. **기준선 자체를 파일럿 4~8주 데이터로 확정**(지금은 정의 불가 — 계측 0) |
| 신뢰 | 신호 기반 검수 우선순위가 가동 중이고, 오탐(정상 매물이 플래그된 비율)이 관측되고 있다. 신고 중위 처리시간이 측정된다 |
| 수익 | 광고주 1곳 이상이 성과 리포트를 받아본 뒤 **재계약(재구매) 1건 실증**, 또는 최소한 가치 지표(전화 CTA 등)가 리포트에 실린다 |
| 운영·법무 | 베트남 법규 확인 항목(§7-2) 완료. OAuth/SMS/FCM 실기기 RC 검증(P0-7) 통과. 신고·검수 처리를 감당할 인력 배치 확정(§7-3) |

판단: 감사의 "파일럿 GO"는 유지하되, **계측(§5 #5·#6)이 없으면 파일럿을 시작해도 전면 판정 근거가 안 쌓이므로, 계측만큼은 파일럿 개시 전 필수**로 격상한다.

## §3. 대표 우려 3건에 대한 시스템 설계

### §3-1. 우려 1 — 매물 진위의 "자동" 관리

**현황 요지(사실)**: 등록 게이트 8종은 있으나(002_trust A-1) 전부 형식 검증이다. 어드민 플래그 4종(`LOW_PHOTOS/ZERO_PRICE/NO_CATEGORY/DUPLICATE`)은 표시 전용, 자동 조치 코드 0건(A-3·A-7). 신뢰 신호 재료: 있음 — `phone_verified_at`·`created_at`·`manner_temp`·제재 이력 / 없음(매번 쿼리 집계) — 거래횟수·신고수·매물 신뢰점수(A-6). Pillow 미설치라 이미지 검증 불가(A-5, D-6 미결).

**설계 원칙(판단)**: "자동"의 의미를 **자동 차단이 아니라 자동 선별(triage)** 로 정의한다. 근거: ① 매물 213건 규모에서 자동 차단의 오탐 1건은 실사용 판매자 1명의 이탈 — 공급 0 상태에서 치명적 ② 오탐률을 측정할 계측이 아직 없다. 측정 없는 자동 차단은 눈 감고 쏘는 것이다.

**자동화 사다리 — 단계별 축소판**:

| 단계 | 내용 | 오탐 비용 | 필요한 신뢰 신호 | 시점 |
|---|---|---|---|---|
| L0 (현재) | 플래그 4종 표시만 | 0 | — | — |

**구성 요소(어디에 붙는가)**:
- 신호 계산: `admin_api/listings.py` `_flags_for()`(`:82-92`) 확장 — 기존 쿼리 시점 계산 방식 유지(신규 테이블·컬럼 없음).
- 큐 정렬: `list_listings` 의 `ORDER BY` 를 플래그 가중합 내림차순으로 — 정렬 옵션으로 추가(기존 최신순 유지).
- 임계값 소재: **1단계는 백엔드 상수(하드코딩)**. 판단: 어드민 편집 화면은 튜닝할 데이터가 생긴 뒤(L2)의 과제 — 지금 만들면 요청 안 된 유연성(카파시 #2).
- 가격 이상치: `modules/pricing/`(§5 #8, D-3·D-4 확정안·D-5 권고안 준수) — 밴드 이탈 시 `PRICE_OUTLIER` 플래그만, 차단 없음.

**오탐 처리 경로**: L1 은 오탐 개념 자체가 없음(순서만). L2 부터는 "운영자 해제 액션 + 판매자 통보 + 감사로그"를 조치와 한 몸으로 구현 — 복구 없는 자동화는 이 문서에서 금지한다.

**명시적 비범위**: 사전승인 큐(즉시 노출은 설계상 강점 — 공급이 생명인 지금 등록 마찰 추가는 자해), 이미지 ML 진위 판정, EXIF 검증(Pillow 미설치 + 판별력 낮음), 개인간 퍼지 중복 탐지(pHash 는 L2 에서 D-6 결정 후).

### §3-3. 우려 3 — 광고 구매의 이유

**현황 요지(사실)**: 판매·심사·계약·대시보드·조회 API 는 완성, **채우는 파이프라인이 0**(002_ads §C 도식). 주 노출면 4종 OFF(`adPlacement.ts:18`), 근접광고도 OFF(`init/174:27`). 유일한 실제 INSERT 코드는 `proximity.py:137-145`(`surface='proximity'`) — 킬스위치+롤업 부재로 이중 차단. 광고주는 대시보드를 열어도 영원히 빈 상태만 본다(002_ads §D).

**정면으로 인정할 것(판단)**: **계측만으로는 광고 구매의 이유가 안 만들어진다.** 공급·트래픽이 0이면 노출수도 0이고, 0을 정확히 계측해봤자 "당신 광고는 아무도 안 봤다"는 정직한 리포트가 나올 뿐이다. 따라서 광고 사업의 인과 사슬은 코드와 운영이 맞물린 **순서 문제**다:

```
[코드] 계측 구축(#5·#6) → [코드] ADS_ENABLED 재개(#10, D-2)
    → [운영] C2C 파일럿으로 트래픽 축적(§7-1과 병행, 4~8주)
    → [데이터] 노출·클릭·가치 지표 축적 → [코드] 가치 지표 훅(#11)·CSV 리포트(#13)
    → [영업] 성과 리포트 기반 재구매 제안 → 전면 문턱 "재구매 1건 실증"
```

**"다시 사겠다"를 만드는 지표 계층(판단)** — 노출수·CTR 은 위생 지표일 뿐이다. 로컬 업체(세차장·식당·수리점)의 실제 가치는 **가게에 온 사람과 걸려온 전화**다:

| 계층 | 지표 | 데이터 소스 | 단계 |
|---|---|---|---|
| 위생 | 노출수, 클릭수, CTR | #6 (D-1 최소범위: impression+click) | 파일럿 |
| 관심 | 광고→업체 프로필 방문, 팔로우, 즐겨찾기 | #11 — CTA 이벤트 훅(B-3). `biz.py:1460-1551`(follow/favorite)에 이벤트 적재 추가 | 전면 |
| **가치** | **전화 CTA 탭**, 길찾기 실행, 소식·가격표 열람 | #11 — "광고로 이번 달 전화 N통"이 재구매 문장의 주어다 | 전면 |
| 인과 | 클릭→24h 내 CTA 어트리뷰션 | 비범위(D-1에서 제외) — 볼륨이 생긴 뒤 | 보류 |

**구성 요소(어디에 붙는가)** — 전부 기존 선례 복제, 신규 컨테이너 없음:
- 수집 API: `POST /market/ads/events` 신설(BFF). `surface` 는 D-19 카탈로그 7종을 **백엔드 Enum 상수로 검증**(CHECK 제약 없음 — D-19 권고). `proximity` 값은 이미 기성값이므로 그대로 수용.
- 프론트 훅: `useAdImpression`(IntersectionObserver 노출 판정)+클릭 핸들러 — `AdCard`/`WorldMapV2`/`AdDetail`/`BizPublic` 4곳.
- 롤업: `backend/app/jobs/rollup_ad_stats.py` 신설, `main.py` 스케줄러 등록(선례 7개 잡). `ad_events`→`ad_daily_stats` 일별 UPSERT. Redis Stream 워커(`ad_worker`)는 **만들지 않는다**(D-1 범위 밖) — 판단: 현 트래픽에서 API 직행 INSERT 로 충분, 워커는 초당 수십 건 이상에서의 과제.
- 리포트: **앱 내 CSV 다운로드 우선(D-9 권고 채택)** — `StreamingResponse` + `csv.writer`(표준 라이브러리, 의존성 0). 판단 근거: 이메일 인프라 0건 + 파일럿 광고주는 소수라 영업 담당이 수동 전달로도 커버 가능. PDF·이메일은 광고주 수가 두 자리 되면 재검토.
- 운영자 가시성: 어드민 광고 성과 화면(#16, 전면) — `BizAdDetailPage` 에 성과 열 추가. 운영자가 광고주보다 성과를 몰라서는 영업이 안 된다.

**계측 전 공백기의 구매 이유(코드 밖, §7-1 연계)**: 판단 — 데이터가 없는 첫 광고주에게 팔 것은 성과가 아니라 **파일럿 파트너 패키지**다: 특가 + 지면 독점(경쟁 광고 없음 — 지금은 사실) + 무료 프로필 기능(소식·가격표, 이미 완성) + "성과 리포트를 받는 첫 업체" 지위. 이는 영업 설계이지 구현 항목이 아니다.

**명시적 비범위**: 어트리뷰션·봇 필터·Redis Stream 워커(D-1 제외 확정), 경매/입찰(수요가 공급을 초과할 때의 문제), 타겟팅 확장(district 외 — 파일럿은 1개 구라 무의미), 자동 결제·정기 갱신(광고주 수십 곳 전까지 수동), 이메일 정기 리포트(인프라 0), 90일 보존 배치·월 파티셔닝(데이터 0행에서 무의미 — 데이터 6개월치 후).

## §6. 순서 판단의 근거

전부 "판단"이다 — 근거를 병기한다.

1. **관점 간 우선순위: 운영자 → 사용자·판매자(신뢰) → 업체.** 근거: 관점 교차 의존표(002_personas §5) — 광고의 가치는 트래픽에서 나오고(연쇄 #1), 트래픽은 신뢰에서 나오며, 신뢰 폐루프의 주어는 운영자다. 업체 관점을 먼저 채우면(노출 재개 등) 성과 없는 광고를 파는 셈이 되어 오히려 재구매 논리를 태운다(D-2 가 계측 후 재개로 확정된 이유와 동일).
2. **∥A(S급 4건)를 맨 앞에.** 근거: 결정 대기 0건·의존 0건이고, 그중 #1·#2 는 기능 개선이 아니라 **폐루프 결함 수정**(신고가 블랙홀, 구제가 요식)이다. 값이 싸고 리스크가 낮은 결함부터 닫는다.
3. **계측(#5·#6)이 신뢰(#7·#8)보다 먼저.** 근거: §3-1 사다리의 L2 이후 전부가 오탐률 실측을 전제한다. 계측 없이 신뢰 시스템을 확장하면 다시 "판정 수단 없음" 상태로 되돌아온다. 단 L1(#7)은 오탐 비용 0이라 계측과 병렬 가능.
4. **#10(노출 재개)은 #6 완료가 하드 게이트.** 근거: D-2 확정 사항. 계측 없는 재개는 "성과를 증명 못 하는 광고"를 다시 파는 것.
5. **전면 5건을 파일럿과 분리.** 근거: §1-2 — 전면 판정 자체가 파일럿 데이터를 전제하므로, 전면 항목을 지금 병행하면 판정 없이 리스트만 부푼다(카파시 #2).
