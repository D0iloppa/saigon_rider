## §0. 한 장 요약

**판정: 현재 SGR의 매물은 "상태 없는 레코드"다.** 등록되면 존재하고, 삭제되면 사라진다. 그 사이에 무슨 일이 있었는지 — 가격이 몇 번 바뀌었는지, 언제 예약됐다 풀렸는지, 같은 물건이 이 계정 저 계정을 돌고 있는지 — 를 남기는 구조가 없다(**확인 필요**, 상태 필드 존재 여부).

**이것이 014의 자기 결함을 하나 만든다**: 014 #34(유동성 패널)의 지표 L-1·L-2·L-4는 전부 **"등록 후 N일 내"** 형태인데, 매물 상태 전이 이력이 없으면 **산출 자체가 불가능하다.** #34는 본 문서 #36에 종속되며, 이는 014 작성 시 누락한 의존이다.

**모니터링 6계층 — 통상 매매사이트가 실제로 돌리는 것:**

| 계층 | 내용 | SGR 현황 | 항목 |
|---|---|---|---|
| ① 생애주기 | 상태 기계 + 전이·가격·끌올 이력 | **없음(추정)** | #36·#37 |
| ② 동일성 | 이미지·텍스트 지문 → 도용·재등록·**물품 순환** 추적 | pHash L2 유보 | #38 |
| ③ 이상 신호 | 시세 이하 가격·재사용 이미지·신규 계정 등 사기 패턴 | 금칙어만 | #39 |
| ④ 판매자 행동 | 등록 속도·동일 모델 반복·다지역 게재 → **업자 식별** | 없음 | #40 |
| ⑤ **서류·명의** | 오토바이 특유 — 등록증 보유, **명의이전 추적** | 없음 | #41 |
| ⑥ 거래 후 | 결과 확인 핑, 명의이전 체크리스트 | 자기신고만 | #42 |

**최대 발견 — 베트남 오토바이 거래는 대면에서 끝나지 않는다.** 2차 출처에 따르면 2023-08-15 이후 중고 오토바이 매매 시 **공증 매매계약 → 번호판·등록증 회수(thu hồi) → 30일 내 신규 등록**이라는 명의이전 절차가 시행·집행되고 있으며, 미이행 시 판매자에게 과태료가, 무번호판 주행 시 차량 압류·벌금이 부과된다. 이는 세 가지를 의미한다:

1. 매물의 **"서류 상태"가 가격과 위험의 결정 변수**다 — 컨디션보다 중요하다
2. 010·014의 `deal_complete`(자기신고)는 **거래의 1단계일 뿐**이다. 진짜 종료는 명의이전 완료다
3. **30일 기한이 존재하는 추적 가능한 후속 절차** → 리마인더·체크리스트는 Chợ Tốt이 하지 않는 **SGR의 명확한 차별화 지점**이다

**보강: 구현 7건(#36~#42) + 미결 결정 4건 + 법무 확인 2건.** 자동 차단·외부 스크래핑·정부 DB 연동은 명시 기각(§9).

## §2. 계층 ① 매물 생애주기 추적

### 2-1. 상태 기계

```
DRAFT → ACTIVE ⇄ RESERVED → SOLD
           ↓        ↓
        HIDDEN   (해제)
           ↓
        EXPIRED (자동, 미갱신 N일)
           ↓
        BLOCKED (운영 조치)  / DELETED (사용자)
```

**판단**: `RESERVED`(예약중)를 별도 상태로 두는 것이 베트남 맥락에서 특히 중요하다. 흥정이 기본값인 시장에서 "이거 아직 있나요?"가 문의의 대다수를 차지하며, 예약 상태 표시는 **헛문의를 줄이고 판매자 부담을 낮춘다.** 010이 식별한 `B-STALE`(판매 완료 매물 방치) 문제의 직접 해법이기도 하다.

`EXPIRED` 자동 만료(예: 갱신 없이 30일)는 재고 신선도의 유일한 자동 장치다. 판단 — 삭제가 아니라 만료여야 한다. 판매자가 되살릴 수 있어야 공급이 보존된다.

### 2-2. 이력 3종

```sql
CREATE TABLE listing_state_log (        -- 상태 전이
  listing_id BIGINT, from_state VARCHAR(12), to_state VARCHAR(12),
  actor_type VARCHAR(10),               -- 'user'|'admin'|'system'
  actor_id BIGINT, reason VARCHAR(40), created_at TIMESTAMPTZ
);
CREATE TABLE listing_price_log (        -- 가격 변동
  listing_id BIGINT, old_price BIGINT, new_price BIGINT, created_at TIMESTAMPTZ
);
-- 끌올은 listings.refreshed_at + 카운터로 충분
```

### 2-3. 이 이력이 없으면 계산 불가능한 것

| 지표 | 필요 이력 | 출처 |
|---|---|---|
| 매물 문의 전환율 (등록 후 14일) | 등록 시각 + 상태 | 014 L-1 |
| 매물 거래 전환율 (등록 후 30일) | SOLD 전이 시각 | 014 L-2 |
| 첫 문의까지 중위 시간 | 등록 시각 | 014 L-4 |
| 재고 신선도 / 유령 매물 비율 | EXPIRED·SOLD 비율 | 운영 |
| 끌올 어뷰징 | refresh 카운터 | 어뷰징 |

**→ 014 #34(유동성 패널)는 #36에 종속된다.** 순서 정정: **#36이 #34보다 먼저.**

### 2-4. 가격 이력의 3가지 용도

1. **가격 인하 알림** — 찜한 매물 가격이 내리면 알림. 당근이 운영하는 기능이며, 014 #18(키워드 알림)과 같은 발송 인프라를 쓴다. 판단: 흥정이 기본값인 시장에서 "가격이 내렸다"는 재방문 유도력이 크다
2. **미끼가(bait) 탐지** — `B-BAIT-PRICE`. 노출 직후 낮은 가격 → 문의 유입 후 인상하는 패턴이 로그에 남는다
3. **시세 산출의 원료** — §4 이상치 탐지의 기준선

**해당: #36(상태 기계·전이 로그) · #37(가격 이력·인하 알림)**

## §3. 계층 ② 동일성 추적 — "같은 물건인가"

### 3-1. 지문 2종

| 지문 | 방법 | 용도 |
|---|---|---|
| 이미지 | perceptual hash (pHash/dHash) — 리사이즈·재압축·경미한 크롭에 강함 | 사진 도용·재사용 탐지 |
| 텍스트 | 정규화(014 #17 함수 재사용) + simhash/shingle | 문구 재사용 탐지 |

**010과의 관계**: 010은 pHash를 L2(파일럿 4~8주 후)로 유보했다. 판단 — **판정은 L2로 미루되, 지문 산출·저장은 지금 시작해야 한다.** 이유는 M3이자 014 B1과 동일: 파일럿 기간의 이미지 지문을 남기지 않으면 L2 시점에 **비교할 과거가 없다.** 지문 생성은 등록 파이프라인에 함수 하나 추가하는 수준(규모 S~M)이고, 판정 로직이 없는 상태로 인덱스만 쌓아도 손해가 없다.

### 3-2. 세 가지 용도 — 도용, 재등록, **물품 순환**

| 패턴 | 탐지 조건 | 의미 |
|---|---|---|
| **사진 도용** (`S-PHOTO-THEFT`) | 동일 지문 · **다른 계정** · 원본이 먼저 등록 | 판매자 피해. 010 목록에 사유 코드 없음 |
| **재등록 어뷰징** | 동일 지문 · 동일 계정 · 삭제 후 재등록 반복 | 끌올 회피. 노출 독점 |
| **물품 순환** ★ | 동일 지문 · **여러 계정을 시간차로 순환** | **업자 위장 또는 도난품 유통** |

**판단 — ★가 오토바이 마켓의 핵심이다.** 같은 바이크가 3개월 새 3개 계정을 거쳐 재판매되면 둘 중 하나다: ① 전문 업자가 개인을 가장하고 있거나 ② 장물이 세탁되고 있거나. 어느 쪽이든 개별 매물 심사로는 절대 잡히지 않고, **지문 이력이 있어야만 보인다.** 업계 표현대로 사기는 계정 간 패턴에 살며, 하나만 보면 멀쩡한 광고가 같은 사진 세트가 여러 이름으로 돌고 있음을 알면 명백해진다.

### 3-3. 오탐 주의

**판단**: 오토바이는 **동일 모델·동일 색상 매물의 사진이 원래 비슷하다.** 특히 판매자가 제조사 카탈로그 이미지를 쓰면 지문이 완전 일치한다. 따라서:
- 지문 일치는 **단독 근거가 될 수 없다** — 계정·시간·지역 축과 결합해야 한다
- 카탈로그 이미지 화이트리스트(반복 등장 지문은 자동 제외)가 필요하다
- 임계값은 실측 전 확정 금지(M3)

**해당: #38(지문 인덱스)**

## §4. 계층 ③ 이상 신호 탐지 — 사기 패턴

### 4-1. 업계 표준 경고 신호 6종과 SGR 대조

업계에서 정리된 사기 매물의 전형적 신호는 **시세를 크게 밑도는 가격, 첫 메시지부터 앱 밖(WhatsApp·이메일·SMS) 유도, 추적 불가능한 방식의 선입금 요구, 여러 계정·지역에 걸친 이미지·문구 재사용, 이력 없는 신규 계정, 대면·검증 거부**다.

| 신호 | SGR 탐지 가능성 | 항목 |
|---|---|---|
| 시세 이하 가격 | 카테고리 중앙값 대비 — **가능** | #39 |
| 앱 밖 유도 | 매물 본문의 Zalo/전화번호 패턴 — 금칙어 확장으로 **가능** | #22 확장 |
| 선입금 요구 | 본문 키워드(chuyển khoản trước 등) — **가능** | #22 확장 |
| 이미지·문구 재사용 | 지문 — **가능** | #38 |
| 신규·빈약 계정 | 가입 경과일 + 매물 수 — **가능** | #39 |
| 대면·검증 거부 | 채팅 내용 — **비범위**(채팅 분석 미도입) | — |

**판단**: 6개 중 5개가 **이미 가진 데이터로 탐지 가능**하다. 새로 필요한 것은 탐지기가 아니라 **신호를 하나의 점수로 모으는 자리**다.

### 4-2. 시세 이상치 — 데이터 부족 국면의 현실적 방법

매물 213건(그중 188건 단일 계정)에서는 정교한 시세 모델이 불가능하다. 단계적으로:

| 단계 | 기준선 | 필요 표본 |
|---|---|---|
| v0 (파일럿) | **카테고리 중앙값** 대비 편차 | 카테고리당 20건 |
| v1 (전면) | 카테고리 × 모델명(정규화) 중앙값 | 모델당 10건 |
| v2 | + 연식·주행거리 보정 | 수백 건 |

**판단**: v0로 시작하되 **경보 임계값을 넉넉히**(예: 중앙값의 50% 이하) 잡아 오탐을 줄인다. 표본이 적을 때 중앙값은 불안정하므로, 표본 미달 카테고리는 **아예 경보를 내지 않는 것**이 정답이다.

### 4-3. 위험 점수 — 판정이 아니라 정렬

```
risk_score = w1·(가격 이상도) + w2·(계정 신규도) + w3·(지문 재사용) 
           + w4·(연락처 노출) + w5·(금칙어 근접)
```

**용도는 오직 하나 — 010 #3 검수 큐의 정렬 가중치.** 자동 숨김·차단 금지(M1). 가중치는 하드코딩(014 B2), 실측 후 조정.

**해당: #39(이상 신호 점수)**

## §5. 계층 ④ 판매자 행동 추적 — 업자(전문판매자) 식별

### 5-1. 패턴 신호

| 신호 | 임계 예시 |
|---|---|
| 등록 속도 | 주 N건 이상 지속 |
| 동일 모델 반복 | 같은 모델을 3건 이상 동시 보유 |
| 다지역 게재 | 여러 구에 동일 매물 |
| 회전율 | 등록→판매 주기가 비정상적으로 짧고 규칙적 |
| 사업자 어휘 | 본문에 "bảo hành"(보증), "trả góp"(할부) 등 |

한국 중고 플랫폼에서도 **동일 상품 다량 판매·여러 동네 게재는 전문판매자(업자) 패턴 감지 대상**으로 다뤄진다.

### 5-2. 판단 — SGR은 업자를 **배제하지 말고 라벨링해야 한다**

당근은 "개인 간 순수 중고거래"를 표방하며 업자를 제재 대상으로 본다. **SGR이 이를 그대로 복제하면 안 된다.** 근거 3가지:

1. **공급이 병목이다.** 매물 213건 중 188건이 단일 계정인 상황에서 대량 등록자를 쫓아내는 것은 자해다
2. **베트남 오토바이 중고 시장은 원래 딜러 중심**이다. Chợ Tốt도 업자와 개인이 공존한다. 개인만 남기는 것은 시장 구조와 싸우는 일이다
3. **문제는 업자 자체가 아니라 위장이다.** 구매자가 상대가 업자임을 알고 거래하면 문제가 없다. 모르고 "개인 급매"인 줄 알았다가 딜러였을 때 신뢰가 깨진다

**따라서 정답은 "업자 후보 플래그 → 비즈 프로필 전환 유도"** 다. 배제가 아니라 **양성화**이며, 이는 곧 **B2B 수익 경로**(업체 광고 상품)로 연결된다. 판단: 이것이 SGR의 구조적 기회다 — 경쟁자가 규제 대상으로 보는 것을 SGR은 고객으로 본다.

**해당: #40(판매자 패턴 라벨)**

## §6. 계층 ⑤ 서류·명의 추적 — 오토바이 특화 (**본 문서 핵심**)

### 6-1. 제도적 사실 (법무 확인 필수)

2차 출처에 따르면, 베트남에서 중고 오토바이 소유권 이전은 2023-08-15 이후 실효적으로 집행되고 있으며 절차는 대략 다음과 같다: **공증사무소에서 매매계약 공증 → 판매자가 관할 경찰서에서 번호판·등록증 회수 절차(thủ tục thu hồi) 이행 → 매매계약일로부터 30일 내 구매자가 신규 등록** . 미이행 시 판매자에게 과태료가, 번호판 없는 차량 주행 시 압류·고액 벌금이 부과된다. 등록증은 통칭 blue/yellow card로 불린다.

**판단**: 이 사실 하나가 SGR 매물 데이터 모델을 바꾼다.

### 6-2. 함의 3가지

#### ① 서류 상태 = 가격·위험의 1차 변수

컨디션 등급보다 서류 상태가 먼저다. 최소 필드:

| 필드 | 값 |
|---|---|
| `paper_status` | 등록증 보유(명의 일치) / 등록증 보유(명의 불일치) / 미보유 / 미확인 |
| `plate_province` | 번호판 등록 지역 (타지 번호판은 이전 비용·절차 차이) |

**명의 불일치**(현 소유자와 등록증상 명의가 다름 — 이전 거래에서 명의이전을 안 한 차량)가 특히 중요하다. 판단: 베트남 중고 시장에 흔한 상태이며, 구매자가 나중에 이전을 못 하거나 추가 비용을 떠안는 분쟁의 원천이다. **강제 입력이 아니라 선택 표시**로 두되(등록 마찰 최소화, 010 A4), 미기재 매물은 랭킹 품질 항에서 감점(014 #19).

#### ② 거래는 대면에서 끝나지 않는다 — `deal_complete`는 1단계다

```
문의 → 약속 → 대면·인수도 → [SGR이 현재 아는 끝]
                              ↓
                    공증 매매계약 → 번호판·등록증 회수 → 30일 내 신규 등록
                              ↑
                    [실제 거래의 끝 — 여기서 분쟁이 터진다]
```

014 §7-4의 11단계 퍼널에 **12단계(명의이전 완료)** 를 추가해야 한다. 판단: 후기(`review_write`)를 대면 직후에 받으면 "그때는 좋았는데 서류가 안 넘어왔다"는 경우를 못 잡는다. 별점의 신뢰도 문제다.

#### ③ 30일 기한 = SGR의 차별화 기회

**Chợ Tốt은 이것을 하지 않는다**(확인 필요, 다만 일반적 리스팅 플랫폼은 거래 후 절차에 관여하지 않는다). SGR이 할 수 있는 것:

- 거래 신고 시 **명의이전 체크리스트** 제공 (필요 서류·절차·기한·예상 비용)
- **D+7 / D+25 리마인더** 알림 (기존 FCM 인프라)
- 완료 확인 → 양측 신뢰 지표에 반영

**판단**: 이것이 010이 규정한 SGR의 차별화 방향 — "또 하나의 마켓플레이스가 아니라 **신뢰 인프라**" — 의 가장 구체적이고 저비용인 실현이다. 코드는 알림 2건과 정적 체크리스트 화면 1개다. 규모 S~M. 효과는 경쟁자가 복제하기 전까지 독점적이다.

### 6-3. 도난 차량 감시 — 내부 watchlist부터

| 단계 | 방법 | 판정 |
|---|---|---|
| v0 | 사용자 도난 제보(`STOLEN_GOODS` 신고, 014 #29) → **내부 watchlist**(번호판 일부·특징) → 신규 매물 대조 시 운영자 경보 | **[전면] 채택 권고** |

| ✗ | 차대번호(VIN) 조회·경찰 DB 연동 | **비범위** — 정부 데이터 접근 리스크(UDI 판단과 동일 논리) |

**주의(법무 확인)**: watchlist 운영은 미확정 혐의를 근거로 개인의 거래를 제약하는 행위다. 판단 — **경보만, 자동 차단 금지**(M1)이며, 매물 삭제는 반드시 사람 판정을 거쳐야 하고 이의제기 경로(010 #2)가 열려 있어야 한다.

**해당: #41(서류·명의 추적 + 체크리스트)**

## §12. 결론 — 대표 보고용 5문장

1. **현재 SGR 매물은 "상태 없는 레코드"** 라, 등록과 삭제 사이에 무슨 일이 있었는지 기록이 없다 — 그리고 이 때문에 014에서 제안한 유동성 지표(등록 후 N일 내 전환율)가 **계산 자체가 불가능**하다. #36이 #34보다 먼저다.

2. 통상 매매사이트의 모니터링은 6계층이며, 사기의 본질은 개별 매물이 아니라 **계정 간 패턴**에 있다 — 같은 사진이 여러 계정을 도는 것이 오토바이 시장에서는 **업자 위장 또는 장물 세탁**의 신호이고, 지문 이력 없이는 절대 보이지 않는다.

3. **업자는 배제가 아니라 라벨링해야 한다.** 당근 모델(전문판매자 제재)을 복제하면 공급 병목 상황에서 자해가 되고, 베트남 오토바이 시장은 원래 딜러 중심이다. 문제는 업자가 아니라 **위장**이며, 양성화는 그대로 B2B 수익 경로가 된다.

4. **최대 발견 — 베트남 오토바이 거래는 대면에서 끝나지 않는다.** 공증 매매계약·번호판 회수·30일 내 신규 등록이라는 법정 절차가 존재하고 미이행 시 과태료가 나온다. 따라서 서류 상태는 컨디션보다 중요한 변수이고, `deal_complete`는 거래의 1단계일 뿐이다.

5. **그 30일 기한이 SGR의 가장 구체적인 차별화 기회다** — 체크리스트 화면 1개와 리마인더 알림 2건(코드 규모 S~M)으로 "또 하나의 마켓플레이스"가 아니라 "거래를 끝까지 책임지는 신뢰 인프라"라는 포지션을 실물로 만들 수 있다. 경쟁자가 하지 않는 영역이다.
