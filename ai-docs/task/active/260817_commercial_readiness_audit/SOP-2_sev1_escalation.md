# SOP-2: SEV1 에스컬레이션 경로

> 근거: [`013_ISSUE_OPS_SYSTEM_4PERSONA.md`](013_ISSUE_OPS_SYSTEM_4PERSONA.md) §2, §7 / [`016_PLATFORM_MASTER_SUPPLEMENT.md`](016_PLATFORM_MASTER_SUPPLEMENT.md) §8-2, §12
> 시점: 파일럿 개시 전
> **전제**: 인력 규모 0.5~2인. 016 §12(이슈 항)와 013 §7은 **24/7 온콜 로테이션을 명시적으로 기각**했다 — 로테이션을 돌릴 인력이 없다. 대신 채택된 축소 원칙은 **"SEV1만 대표 직통"**이다. 본 문서는 이 축소된 원칙을 그대로 반영한다. 새로운 온콜 체계를 설계하지 않는다.
> **법무 확인 관련 표기**: 응답 시한·통지 의무 등 법적 근거가 있을 수 있는 항목은 전부 `[법무확인 필요 — L-n]`으로 표시했다. 특정 시행령·조문·시한을 확정 사실로 서술하지 않는다.

## 0. 공통 원칙

- 이 문서가 다루는 8개 카테고리는 **모두 SEV1**이다 — SEV1이 아닌 사고는 SOP-1로 처리하고 이 문서를 적용하지 않는다.
- "대표" "운영 담당"은 역할명이며 특정 개인명을 문서에 못 박지 않는다 — 인력 교체 시 이 문서를 고칠 필요가 없게 한다.
- 통보는 **야간·주말 포함**이다. SEV1은 업무시간 제약을 받지 않는다 — 이것이 "SEV1만 대표 직통"이 의미하는 바다(전체 온콜이 아니라, 이 8종만 시간 무관하게 뚫린 경로).
- 임시 조치는 전부 **수동**이다 — 자동 잠금·자동 롤백 트리거는 없다(013 §7, 016 §12 자동화 금지 원칙과 동일선상).

## 1. 계정 탈취 (`S-HIJACK`)

- **누구에게**: 운영 담당 → 확인 즉시 대표에게 요약 통보(피해 규모가 크거나 판단이 애매할 때는 즉시, 아니면 처리 후 사후 보고 가능)
- **목표 통보 시각**: 발견 즉시, 지체 없이. 구체 분 수 확정치는 없음 — "야간이라도 즉시" 원칙만 확정
- **야간·주말**: 포함
- **임시 조치(수동)**: 해당 계정 즉시 잠금(로그인 차단) → 원 소유자 본인 확인(가입 정보·직전 거래 내역 등 수동 대조) 후에만 잠금 해제
- **1차 대응 체크리스트**:
  1. 계정 잠금 처리 완료 확인
  2. 탈취 이후 발생한 거래·메시지·매물 등록 내역 전수 확인(피해 확산 여부)
  3. 원 소유자 연락 채널(가입 시 등록 정보) 확보 및 본인 확인 시도
  4. 탈취 경유 흔적(로그인 IP·시각 등) 있으면 감사 로그에 남김
  5. 본인 확인 완료 시 비밀번호 재설정 안내 후 잠금 해제

## 2. 개인정보 유출 (`B-PII`, `O-DATA-LEAK`)

- **누구에게**: 운영 담당 확인 즉시 대표 직통
- **목표 통보 시각**: 발견 즉시
- **야간·주말**: 포함
- **임시 조치(수동)**: 유출 경로(버그·오설정·유출 게시물 등) 수동 차단. 유출 범위가 확인되기 전까지 관련 기능 임시 비활성 검토
- **1차 대응 체크리스트**:
  1. 유출 범위(대상자 수·항목) 최대한 파악
  2. 유출 경로 차단(코드 패치·게시물 삭제·권한 회수 등)
  3. `[법무확인 필요 — L-5]` 통지 의무·기한·대상 범위 확인 전까지 외부 공표는 대표 판단 없이 하지 않음
  4. 사고 기록(시각·범위·조치)을 결과 코드와 함께 남김
  5. 재발 방지를 위한 원인(코드/설정/사람) 규명

## 3. 도난 오토바이 (`B-STOLEN` / `STOLEN_GOODS`)

- **누구에게**: 운영 담당 확인 즉시 처리(정상 근무시간 내 접수 다수) — 판단 애매하거나 언론·SNS 노출 우려 시 대표 통보
- **목표 통보 시각**: 접수 즉시 게시중단(대표 통보와 별개로 즉시 실행)
- **야간·주말**: 포함(게시중단 자체는 대표 승인 불필요, 즉시 실행)
- **임시 조치(수동)**: 해당 매물 즉시 게시중단 + 등록 계정 임시 정지. 플랫폼이 경찰 신고를 대리하지 않음 — 피해자·신고자에게 관할 기관 신고를 안내
- **1차 대응 체크리스트**:
  1. 매물 게시중단, 등록자 계정 임시 정지
  2. 신고 내용(차량 정보·신고자 연락처) 보존
  3. 서류 보유 여부 필드(`cà vẹt` 표시) 확인 — 미보유 표시 매물이면 위험 신호 기록에 반영
  4. 구매자(있는 경우) 피해 확인 및 관할 기관 신고 안내
  5. 등록자 이의 제기 시 재게시는 신고 철회 또는 증빙 확인 후에만

## 4. 규제기관 정보 요청 (`O-REGULATOR`)

- **누구에게**: 발견 즉시 대표 직통(운영 담당이 임의로 응대하지 않음)
- **목표 통보 시각**: 공문·요청 확인 즉시. `[법무확인 필요 — L-2]` — 법정 응답 시한이 존재할 수 있으나 그 기한을 여기서 단정하지 않는다. 대표 직통 통보 자체는 "즉시"로 고정
- **야간·주말**: 포함
- **임시 조치(수동)**: 없음(요청에 대한 응대는 대표·법무 확인 후에만 — 임의 답변 금지)
- **1차 대응 체크리스트**:
  1. 요청 원문(발신 기관·요청 항목·형식) 보존
  2. 대표에게 즉시 원문 전달
  3. `[법무확인 필요 — L-2]` 응답 창구 지정 요건 확인 전까지 비공식 답변 자제
  4. `[법무확인 필요 — L-1]` SGR의 사업자 분류(전자상거래 거래소 해당 여부) 확인 필요성 재확인
  5. 대표·법무 확인 후 공식 창구로 응답

## 5. 전체 서비스 장애 (`O-OUTAGE`)

- **누구에게**: 운영 담당 즉시 대응, 복구 불가·장기화 시 대표 통보
- **목표 통보 시각**: 헬스체크 경보 발생 즉시 확인 착수. 30분 내 복구 안 되면 대표에게 상황 공유
- **야간·주말**: 포함
- **임시 조치(수동)**: 재기동 절차(코드 밖 SOP, 별도 문서) 수행. 자동 재기동 트리거 없음 — 사람이 확인 후 재기동
- **1차 대응 체크리스트**:
  1. 장애 범위 확인(전체/일부 서비스, BFF/Engine/admin_frontend 중 어디)
  2. 재기동 절차 수행
  3. 복구 후 데이터 정합성(진행 중 거래·조치 영향) 확인
  4. 30분 이상 지속 시 대표 통보
  5. 사후 원인 기록

## 6. 대량 오조치 (`O-MASS-ERROR`)

- **누구에게**: 발견 즉시 대표 직통(피해 확산 중일 가능성)
- **목표 통보 시각**: 발견 즉시
- **야간·주말**: 포함
- **임시 조치(수동)**: 오조치를 발생시킨 기능/배치 작업 즉시 중단. 개별 건 확인 후 수동 롤백(자동 일괄 롤백 도구 없음 — 013 §2-4 결손으로 인지된 상태)
- **1차 대응 체크리스트**:
  1. 오조치 원인(배치·설정·인적 오류) 확인 및 원인 동작 중단
  2. 감사 로그로 영향받은 건수·대상 파악
  3. 영향받은 당사자에게 순차 통보 및 개별 복구
  4. 대표에게 규모·복구 계획 보고
  5. 재발 방지 조치(원인이 반복 가능한 구조인지 확인)

## 7. 사칭 업체 (`P-IMPERSONATE`)

- **누구에게**: 운영 담당 확인 즉시 게시중단, 실제 피해 업체가 확인되면 대표 통보(명예훼손·분쟁 리스크)
- **목표 통보 시각**: 신고·확인 즉시 게시중단
- **야간·주말**: 포함(게시중단 자체는 즉시 실행)
- **임시 조치(수동)**: 사칭 프로필 즉시 게시중단. 실 업체 확인 시도(공개 정보 대조)
- **1차 대응 체크리스트**:
  1. 사칭 프로필 게시중단
  2. 실제 업체 존재 여부·피해 확인
  3. 등록자 계정 조치(정지 여부는 사칭 의도 확인 후)
  4. 실 업체에 통보(연락 가능한 경우)
  5. 재등록 방지를 위한 심사 강화 여부 검토

## 8. 선입금 사기 (`B-FRAUD-PREPAY`)

- **누구에게**: 운영 담당이 확인 즉시 처리, 피해 규모가 크거나 반복 패턴이면 대표 통보
- **목표 통보 시각**: 신고 확인 즉시 계정 정지
- **야간·주말**: 포함(계정 정지 자체는 즉시 실행)
- **임시 조치(수동)**: 가해 계정 즉시 정지. 플랫폼이 형사 신고를 대리하지 않음 — 피해자에게 관할 기관 신고 안내
- **1차 대응 체크리스트**:
  1. 가해 계정 즉시 정지
  2. 피해자 신고 내용·증빙(대화 내역 등) 보존
  3. 동일 계정의 다른 거래 이력 확인(추가 피해자 여부)
  4. 피해자에게 관할 기관 신고 절차 안내
  5. 반복 패턴(동일 수법 재등록 등) 확인되면 대표 통보 및 예방 안내 문구 검토(SOP-4 연계)

## 9. 이 문서에 없는 것

- 24/7 온콜 로테이션, 교대 근무표, 야간 당직자 지정 — 인력 규모상 설계하지 않는다(위 §0 참조)
- SEV2~4 사고의 에스컬레이션 경로 — SOP-1 매트릭스로 처리, 대표 직통 대상 아님
- 법정 응답 시한의 구체 수치 — `[법무확인 필요]`로만 표기, 확정 전까지 임의 시한 설정 금지
