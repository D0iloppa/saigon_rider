# 거래 요청 → 판매자 승인 → 예약중 → 거래완료/취소 — 플로우 설계안 v2 (2026-09-28)

> **목적** "예약중은 누구와?"를 시스템이 항상 알게 하되, 구매자 마찰과 판매자 승인 노동은 늘리지 않는다. 같은 판매자의 매물 여러 개를 한 번에 거래하는 경우까지 한 모델로 푼다. **설계 원칙(대표)**: *기본 기능(상태 변경·채팅·약속)은 단순하게 제공하고, 그 위에 단계별 퀵액션을 합리적으로 얹어 유기적으로 편하게.* 설계 문서다 — 코드·스토리보드는 건드리지 않았다.
> **용어(대표 결정 260928)** 매물 배지 = 판매중 / 예약중 / 거래완료(+기간만료). "거래" = 과정 전체, "약속" = 시간·장소를 정하는 행위. 신규: **거래 세트(세트)** = 한 방에서 구매자 1명이 판매자 1명과 *한 번에 거래하는 물품 묶음*(당근 "한 번에 거래하는 물품"). **세트 항목** = 세트 안의 매물 하나.
> **근거 코드** `backend/app/routers/market.py`(줄번호 인라인), 스키마 `database/init/105·110·232·240`, 프레임 ID는 `260919_service_flow_review_kit.md`. v1 → v2 변경은 말미 "변경 이력".

> **⚠️ 부분 대체(2026-09-29, r7 — 약속 독립 원칙).** 이 문서의 §3.3 칩 매트릭스, §3.4 "약속"·"결제" 행, §5 "트랜잭션 PK(=약속)·약속 게이트(r4) 유지", §7 Q2(d2 이중 약속 불허)는 킷 `F-N-02 FR-7`·`F-DM-02 FR-1 판정(r7)`로 대체됐다 — 약속은 거래 상태와 독립, 게이트 폐기, 이중 약속 허용, 결제는 세트 귀속(약속은 퀵액션 제안). 나머지는 유효.

## 0. 한 줄 결론

**예약중·거래완료는 언제나 판매자의 명시적 상태 변경**이다 — 단, 그 변경을 (a) *상대 방 안에서* 하면 상대가 자동으로 정해지고(당근 세트 바 "판매중 ∨"), (b) *매물 상세에서* 하면 이 매물로 대화 중인 상대 목록에서 고른다. 약속 생성·가격제안 수락은 상태를 **자동으로 바꾸지 않고 판매자에게 묻는다**("예약중으로 변경할까요? [변경]"). 방마다 **거래 세트** 하나가 구매자의 의사("이것들을 살게요")를 담고, 약속·결제·완료·후기는 세트당 1벌, 매물 간판은 세트 항목에서 파생된다.

## 1. 문제 정의 — 시나리오별 현재 모델의 구멍

| # | 시나리오 | 현재 동작(코드) | 무엇이 틀어지나 |
|---|---|---|---|
| 1 | 구매자 1명, 채팅→약속→만남 | 약속 수락→RESERVED→완료→SOLD | 동작. 약속 없이 합의하면 #4 |
| 2 | **B(정가) / C(−10k) 동시 문의** | [예약중] 세그먼트 = **상대 없는 RESERVED** | 누구 예약인지 기록 0. 판매자가 매물 단위로 "누가 뭘 요청했나"를 볼 화면이 없다(채팅 탭뿐). 두 방 제안을 **둘 다 수락 가능** |
| 3 | 협상 후 수락 | `accept_price_offer`(3148) 상태 불변 | 수락 뒤 다음 행동을 아무도 안 알려 준다 |
| 4 | 채팅만으로 합의 | 수동 RESERVED, 딜핑 SOLD | 상대 없음 → **이력·후기 불가**(`/trades`:3226 약속 기반) |
| 5 | **같은 판매자 매물 N개** | 방에 매물 N개 연결(240)+아코디언 | 약속·트랜잭션 매물당 1개(105·232). 가격제안은 `conv.context_id` 고정·**방당 1건 supersede**(3068) → 매물 B 제안이 A를 지움. 합의가(2759)·게이트(1810)도 방 기준 |
| 6 | 예약 후 상대 교체(B 노쇼→C) | 약속 취소→ON_SALE→새 약속 | 약속 없는 예약은 교체 개념·통지 없음 |
| 7 | 만남에서 일부만 구매 | 없음 | 매물별 따로 완료·취소 |
| 8 | 앱 밖에서 팔고 완료 | 딜핑 SOLD(상대 없음) | 판매 이력에 안 뜸. FR-4 "대화 상대 없이 예약"은 대표 결정과 충돌 |
| 9 | 구매자가 그만둠 | 약속 취소만 | 약속 없는 예약은 못 푼다 |
| 10 | 예약중 매물 기간만료 | 상태만 EXPIRED | 예약 상대 처리 규칙 없음 |

공통 원인: "예약중"이 상대 없는 간판 값이고, 상대 기록이 약속에 종속돼 있으며, 방 단위(제안·합의가)와 매물 단위(약속)가 섞여 있고, **판매자에게 매물 중심의 요청 관리 화면이 없다**.

## 2. 후보 모델 비교

- **(a) 요청·승인형**: [가격제안]·[채팅하기]가 요청 레코드 생성 → 판매자 승인 게이트 → 예약중.
- **(b) 세트 + 판매자 명시 상태 변경**(권고): 세트는 채팅만으로 생기고(승인 없음), 예약중은 판매자가 방 안 또는 매물 상세에서 바꾼다. 약속·제안 수락은 프롬프트만. 약속·결제·완료·후기 세트당 1벌.
- **(c) 당근 최소형**: 매물에 `reserved_for` 한 칸. 묶음 없음.

| 기준 | (a) | (b) | (c) |
|---|---|---|---|
| 경쟁 구매자 명료성 | ◎ | ◎ 매물 상세 [대화중인 채팅 n]·[가격 제안 n] 목록 + 방 안 상태 변경 | ○ |
| 구매자 마찰 | ✕ 승인 전 예약 불가 | ◎ 채팅·제안 그대로 | ◎ |
| 채팅만 거래 | △ | ◎ 방 안 "판매중 ∨" 1탭 | ◎ |
| 다중 매물 | ✕ N승인 | ◎ 세트 단위 | ✕ |
| 이중 판매 방지 | ○ | ◎ 항목 유니크 | ○ |
| 이력·후기 | ○ | ◎ 항목 = 이력 행 | ✕ |
| 구현 델타 | 큼 | **중~큼** | 작음 |
| MVP | ✕ | ○ (§6) | ○, #4·#5·#6 미해결 |

**시장 참고.** 당근은 승인 절차 없이 판매자가 상태를 바꾼다 — 방 안 세트 바 "판매중 ∨" 시트(상대 = 그 방)와 매물 상세 하단 `[♡] [가격 제안 n] [대화중인 채팅 n]`(매물 중심 요청 관리). 약속 생성은 자동 예약이 아니라 "예약중으로 변경하시겠어요?" 프롬프트. 승인형은 플랫폼이 돈을 쥐는 곳(번개장터 안전결제·Mercari)에서만 보상이 있다.

## 3. 권고 모델 — 세트 + 판매자 명시 상태 변경

### 3.1 엔티티와 상태기계

```
거래 세트(trade_sets): conversation_id · buyer_id · seller_id · status · appointment_id?(1:1)
   ACTIVE ──[거래완료]──▶ COMPLETED     ACTIVE ──전 항목 제거·취소──▶ CANCELLED     ※ 방당 ACTIVE 1개, 종결 후 [물품추가]=새 세트
세트 항목(trade_set_items): set_id · listing_id · status · agreed_price_vnd · added_by
   INQUIRY(문의중) ──판매자 [예약중]──▶ RESERVED(예약중) ──[거래완료]──▶ COMPLETED
        └──제거·타인 예약──▶ REMOVED                └──[판매중]·[예약 취소]──▶ 문의중 복귀 / CANCELLED
   ※ 유니크: listing_id WHERE status IN (RESERVED, COMPLETED)   ※ 문의중 → COMPLETED 직행 허용(판매중→거래완료, 당근 동형)
약속(기존): PROPOSED → ACCEPTED → COMPLETED/CANCELLED — 세트당 1건. **수락해도 매물 상태 불변**(현행 2438 자동 RESERVED 제거) → 판매자 프롬프트
가격제안(기존): 항목 단위. 수락해도 상태 불변(현행 유지) → 판매자 프롬프트
매물 간판(파생): RESERVED 항목 → 예약중 / COMPLETED → 거래완료 / 그 외 → 판매중
```

|---|---|---|---|
| 세트 생성 + 항목 문의중 | [채팅하기]·[가격제안]·[물품추가]·같은 판매자 다른 매물 [채팅하기] | 양측 | 구매자 담기 → **묶음 요청 카드**(§3.4) / 판매자 담기 → "이 물품도 함께 어때요?" 카드. 승인 없음 |
| 항목 예약중 | ① 방 세트 바 "판매중 ∨" → [예약중](상대 = 이 방) ② 매물 상세 "판매중 ∨" → [예약중] → 대화 목록에서 상대 선택(F-S0-02 FR-4) ③ 프롬프트 [변경] | 판매자만 | 세트의 문의중 항목 전부 RESERVED → 매물 예약중. **다른 구매자 세트**의 같은 항목 → REMOVED + PROPOSED 제안 자동 DECLINED + 시스템 메시지. 타인에게 예약중인 항목이 섞여 있으면 교체 확인 1회(매물명 나열) |
| 항목 문의중 복귀 | "판매중 ∨" → [판매중] | 판매자 | 매물 판매중(다른 RESERVED 없을 때). 가역·무확인·토스트, 구매자 알림. PAYMENT_REPORTED 이후 불가(409) |
| 항목 취소 | 구매자 [예약 취소](사유 칩) | 구매자 | 항목 CANCELLED, 매물 판매중, 판매자 알림 |
| 세트 완료 | "판매중 ∨" → [거래완료] / 칩 [거래 완료] / 약속 카드 / 매물 상세 → 상대 선택 | 판매자, **확인 1회**("B님과 N건 · 총 55,000원 거래를 완료할까요? 되돌릴 수 없어요") | 세트 항목 전부 COMPLETED(제외할 물품은 먼저 [물품편집]에서 제거) → 매물 거래완료 → **후기 시트 즉시 1회**(판매자) + 구매자 후기 요청 푸시(#9) |
| 프롬프트(자동 변경 없음) | 약속 ACCEPTED 직후 / 제안 수락 직후 / 입금 확인 직후 / 약속 취소(사유 연락 안 됨·다른 곳 거래) | 판매자 방 안 카드 | "B님과 약속을 만들었어요. 매물을 예약중으로 변경할까요? [변경] [나중에]" / "거래를 완료할까요? [거래 완료]" / "판매중으로 되돌릴까요? [되돌리기] [유지]". 무응답 시 상태 유지, FR-3 핑이 재질문 |
| 예약중 매물 만료 | 만료 잡 | 시스템 | RESERVED 항목 있으면 보류 |

**B/C 해소.** 판매자는 B 방에서 "판매중 ∨" → [예약중] 1탭. X는 B에게 예약중, C 세트의 X는 빠지고(Y 문의중 유지) C에게 "X는 다른 분과 거래가 진행돼 빠졌어요". X 상세 [대화중인 채팅 2]에서 B 행에 예약중 배지. C가 X+Y를 원하고 B가 X만 원하면 판매자는 두 방(또는 목록 화면)에서 세트 요약("X 외 1 · 총 55,000")을 보고 고른다.

### 3.2 "거래 요청"과 판매자의 요청 관리 화면

**세트가 곧 요청**이다(승인 없음). 판매자가 요청을 *매물 단위로* 보는 자리 — 당근 동형으로 신설:

| 화면 | 내용 | 퀵액션 |
|---|---|---|
| 판매자 매물 상세 하단 바 `[♡ n] [가격 제안 n] [대화중인 채팅 n]` | 카운터 = 진입점. 미응답 제안·새 메시지는 점 배지 | — |
| **F-S0-02 FR-5 가격 제안 목록** | 행: 상대(티어칩) · 금액 · 상태(응답 대기/수락/거절/마감) · 시각 · 세트 요약 | 행 [수락][거절](대기 건) — 수락 시 프롬프트 §3.1. 행 탭 → 방 |
| **F-S0-02 FR-6 대화중인 채팅 목록** | 행: 상대 · 마지막 메시지 · "X 외 1 · 총액" · 배지(약속/제안/예약중) | 행 탭 → 방. **선택 모드** = 기존 FR-4(라디오 + [예약하기]/[거래 완료]) — 상태 "판매중 ∨"에서 예약중·거래완료를 고르면 이 목록이 선택 모드로 열린다 |
| 매물 상세 본문 상태 필 "판매중 ∨" | 시트 [판매중][예약중][거래완료][닫기] | 예약중·거래완료 → FR-6 선택 모드(상대 필수, "대화 상대 없이 예약" 제거). 완료 모드의 "앱 밖에서 팔았어요" → 거래완료(상대·후기 없음, 이력 "앱 밖")는 유지 |

**예약자 선택 화면 상세 (대표 추가 피드백 260928, 당근 참조)** — 위 "판매중 ∨" → [예약중]/[거래완료] 선택 시 FR-6 선택 모드의 구체 형태:
- 상태 필은 **셀렉트 박스형** "판매중 ∨"(현재 [판매중/예약중] 토글 대체). 탭 → 시트 [판매중][예약중][거래완료][닫기].
- [예약중] → 전체 화면 **"예약자 선택"**: 상단 "거래할 물품"(썸네일·제목) → 이 매물로 채팅한 상대 목록(아바타·닉네임·동네·**"마지막 대화 N분 전"**, 라디오 단일 선택) → 하단 고정 CTA [예약자 선택]. 목록 아래 링크 **"최근 채팅 목록에서 예약자 찾기"**(이 매물로 대화하지 않은 최근 채팅 상대 — 오프라인 합의·다른 매물 방에서 합의한 경우).
- [거래완료]도 같은 화면(제목 "구매자 선택", CTA [거래 완료]) + "앱 밖에서 팔았어요" 유지.
- **채팅방 안에서 바꾸면 이 화면을 건너뛴다** — 상대가 이미 그 방의 상대로 정해져 있으므로 시트 선택 즉시 적용.
- 하단 바 카운터는 해당 요청이 있을 때만 의미가 있으므로 가격 제안 불가 매물은 `[♡][대화중인 채팅 n]`만(당근 동일).

### 3.3 방 안 세트 바 · 상태 시트 · 단계별 퀵액션 칩

**세트 바(F-DM-02 FR-1)**: `대표 썸네일(+N)` · `[판매중 ∨](판매자 탭 = 상태 시트 / 구매자 = 라벨)` · "캐리어 외 1" · **총 55,000원**. 바 아래 **칩 행**은 단계·역할로 바뀐다:

| 단계 | 판매자 칩 | 구매자 칩 |
|---|---|---|
| 문의중(약속 없음) | [약속 잡기] [물품편집] | [가격 제안] [물품편집] ([약속 잡기]는 게이트 r4 충족 시) |
| 예약중(약속 없음) | [약속 잡기] [물품편집] [거래 완료] | [약속 잡기] [물품편집] [예약 취소] |
| 약속 확정 | [📅 오늘 17:00] [결제 방법](QR 등록/현금, E) [📍 위치 공유] [물품편집] | [📅 오늘 17:00] [길안내] [📍 위치 공유] [물품편집] — 창 안: [물건 확인했어요] → [송금했어요]/[현금 건넸어요] |
| 송금 신고됨 | [📅] [입금 확인] [아직 안 왔어요] · 편집 잠금 | [📅] "입금 확인 대기" [문제가 있나요?] |
| 입금 확인됨 | [거래 완료] | [완료 요청] |
| 거래완료 | [후기 보내기]/[내 후기 보기] · [물품추가]=새 세트 | 동일 |
| 취소됨 | [다시 약속 잡기] [물품편집] | 동일 |

[📅] 탭 = 약속 카드(변경·취소), [결제 방법]·[송금했어요] = 기존 거래 화면(F-S6-01) 바로가기. 당근 [송금요청]·안심결제 배너는 당근페이 전용 — 우리는 E 패키지(QR 수동·현금)가 그 자리. 프롬프트 카드(§3.1)는 칩 행 바로 아래 1장만, 처리·[나중에]로 소멸.

**상태 시트(F-DM-02 FR-7, 판매자)** `[판매중] [예약중] [거래완료] [닫기]` — 대상은 *이 세트의 항목 전부*, 시트 제목에 "B님과 · N건 · 총 55,000원". 판매중·예약중은 무확인(가역, 토스트+실행취소 5초, 상대 알림), 거래완료는 확인 1회 → 후기 시트. 타인 예약중 항목 포함 시 교체 확인, 거래완료 항목은 제외 표시.
