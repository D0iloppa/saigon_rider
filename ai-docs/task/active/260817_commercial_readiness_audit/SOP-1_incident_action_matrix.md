# SOP-1: 유형별 조치 매트릭스 (Incident Action Matrix)

> 근거: [`013_ISSUE_OPS_SYSTEM_4PERSONA.md`](013_ISSUE_OPS_SYSTEM_4PERSONA.md) §2, [`016_PLATFORM_MASTER_SUPPLEMENT.md`](016_PLATFORM_MASTER_SUPPLEMENT.md) §8-2
> 시점: 파일럿 개시 전
> **법무 확인 관련 표기**: 본 문서에 나오는 어떤 항목도 특정 법조문·시행령 번호·법정 응답 시한을 확정 사실로 서술하지 않는다. 법적 근거가 관련될 수 있는 항목은 전부 `[법무확인 필요 — L-n]`으로 표시했으며, 016 §11-2 L-1~L-7은 전부 **미확인**이다.

## 0. 이 문서의 성격

**이것은 인간 운영자의 판단을 돕는 참고표이며, 자동 조치 규칙 엔진이 아니다.**

016 §12(하지 않을 것 — 통합 기각 목록, "이슈" 항)는 "사고 유형별 자동 조치 룰 엔진"을 명시적으로 기각했다 — 근거는 010 §3-1 L3 기각과 동일 논리: **실측 데이터가 쌓이기 전에 자동화하면 오탐이 오탐을 낳는다.** 013 §7도 같은 항목을 동일 이유로 재확인했다.

따라서 아래 표의 "권장 조치"는:
- 코드가 자동으로 실행하는 액션이 아니다 — 운영자가 사안을 접했을 때 참고하는 **기본값(default) 제안**이다.
- 사안별 정황(재발 여부, 피해 규모, 증거 확실성)에 따라 운영자가 상향·하향 조정할 수 있고, 그래야 한다.
- 조치 후에는 010 #26(사고 유형·결과 코드) 체계에 따라 **처리 결과 코드 없이 종결 불가** — 이 표를 참고해 조치했더라도 최종 판단과 근거는 종결 코드에 남겨야 한다.

**조치 용어 정의**: 경고(당사자에게 서면 경고, 기록만) / 게시중단(해당 매물·소재·프로필 비공개, 재게시 가능) / 정지(계정 이용 제한, 기간 명시) / 무조치(접수·기록만, 액션 없음). 복수 조치 병기 시 "우선 조치 → 재발 시 조치" 순서.

## 5. 사용 방법

1. 사고 접수 시 코드 매칭 → 이 표에서 심각도·권장 조치 확인
2. SEV1이면 **즉시 SOP-2("SEV1 에스컬레이션 경로")로 이동** — 이 표만으로 종결하지 않는다
3. 권장 조치는 시작점일 뿐, 정황에 따라 운영자가 조정
4. 조치 후 반드시 결과 코드 남기고 종결 (#26 규칙)
