## 0. 분류 기준 — "출시를 막는 것"과 "출시 후 처리"를 가른 근거

- **§1 출시를 막는 것**: (a) 출시 게이트(감사 9게이트)의 FAIL/부분 판정에 직결되거나, (b) 출시 시점(= 실사용자·실데이터가 생기는 순간)부터 위험이 **즉시 실현**되거나, (c) 앱이 **공표한 사실과 실동작이 어긋나는** 법적 성격의 것.
- **§2 출시 후 처리해도 되는 것**: (a) 기능이 이미 OFF/가드된 채로 출시 가능하거나, (b) 실사용자·실데이터·수익화가 생겨야 비로소 의미가 생기거나, (c) 대표가 명시적으로 후순위 결정을 내린 것.

**현재 출시 판정은 NO-GO** — §1 이 비어야 GO 가 된다.

## §1. 출시를 막는 것

### 1-1. 서명 빌드 + 실기기 E2E — B-1 (게이트 7 FAIL 의 전부)

1. **무엇인가**: 앱을 스토어에 올릴 수 있는 **서명된 Android/iOS 빌드**를 만들고, 실제 휴대폰에서 GPS 권한·백그라운드 위치·FCM 푸시(등록/토큰 회전/딥링크)·OAuth 3종(Zalo/Google/Apple) 로그인 복귀·오프라인 동작을 한 번씩 확인하는 일이다. 지금까지의 모든 검증은 웹 브라우저와 서버 기준이고, **휴대폰에서 실제로 돌려본 적이 없다.**
2. **왜 지금 못 닫는가** — **기술적 제약(환경 부재)**: 개발서버(WSL2)에 Android SDK·Xcode 가 없고, 실기기와 앱 서명키도 없다. 브라우저에서는 `native.platform === 'web'` 이라 강제 업데이트(F-19) 같은 네이티브 경로가 **원천적으로 실행되지 않는다**(E2E 로도 검증 불가 — ADR "검증 하네스" 절).
3. **선행조건**: ① 서명키 생성(Android keystore / Apple 인증서·프로비저닝) ② 빌드 머신(Mac 포함) ③ 실기기 최소 Android 1대 + iPhone 1대. 코드 쪽 선행은 **이미 끝나 있다** — `Device.getAppVersion()` 이 native 서브모듈에 커밋·push 됐다(`4da4291`). 다만 이 코드는 **컴파일도, 실기기 검증도 못 한 상태**다.
4. **누가**: 대표/모바일 담당 (빌드 환경·기기·서명키가 대표 소관).
5. **안 닫으면**: ⓐ GPS 권한 팝업이 안 뜨거나 백그라운드에서 궤적이 끊겨도 출시 후에야 안다. ⓑ FCM 등록이 실패하면 알림 전체가 무음인 채 배포된다. ⓒ **F-19 강제 업데이트가 실기기에서 발동하는지 아무도 확인 못 했다** — `getAppVersion()` 네이티브 코드에 오타 하나만 있어도 fail-open 안전망(③ `unknown` → 차단 안 함)에 걸려, 치명 버그 배포 시 구버전 사용자를 영영 차단할 수 없다. ⓓ OAuth 복귀 딥링크가 깨지면 로그인 자체가 안 되는 앱이 스토어에 올라간다.
6. **닫힘 확인**: 서명 빌드를 실기기에 설치하고 위 체크리스트(GPS·백그라운드·FCM 3종·OAuth 3종 복귀·오프라인·**구버전 설치 후 F-19 차단 화면 발동**)를 1회씩 통과한 기록. 증적 항목은 [`260802_launch_evidence_checklist.md`](./260802_launch_evidence_checklist.md) 게이트 7.

### 1-2. Engine `ENGINE_SERVICE_KEY` 회전 + 모바일/BFF identity 분리 — B-3 (게이트 1 잔여)

1. **무엇인가**: 모바일 앱이 GPS 를 서버(Engine)로 보낼 때 쓰는 **비밀 키가 앱 안에 내장된 전역 키 하나**다. 공개 경로는 nginx allowlist 로 `POST /api/sre/sreMessage` 하나만 열어뒀지만, 그 하나가 여전히 전역 키 단일 비교로 열린다 — `engine/app/deps.py:12` `verify_service_key()` 가 `key != settings.engine_service_key` 하나만 보고, `engine/app/routers/message.py:25` 가 그 의존성으로 sreMessage 를 지킨다(2026-08-02 재확인).
2. **왜 지금 못 닫는가** — **선행조건**: 키를 사용자·기기·만료가 결속된 단기 토큰으로 재설계하면 **그 토큰을 쓰는 새 앱을 배포해야** 하는데, 앱 배포 경로(스토어 등록·서명 빌드 = 1-1)가 아직 없다. 지금 회전만 하면 기존 배포본(있다면)이 전부 끊기고, 재설계 없이 회전만 하면 같은 구조가 반복된다.
3. **선행조건**: ① 1-1 의 앱 배포 경로 확보 ② 개발이 단기 토큰 설계·구현 ③ 대표가 운영 키 회전 실행. 순서는 "설계·구현 → 신규 앱 배포 → 구 키 폐기".
4. **누가**: 개발(설계·구현) + 대표(키 회전은 운영 자격, 앱 재배포는 스토어 절차).
5. **안 닫으면**: 앱 바이너리에서 키를 추출한 공격자가 **임의 사용자의 GPS 궤적·이벤트를 위조 주입**할 수 있다 → 라이딩 미션·RP 보상 조작(가짜 주행으로 보상 수령), 타인 계정의 위치 데이터 오염. 특권·경제 변경 경로(가챠·상점·크레딧)는 nginx 에서 404 로 차단돼 있어 "즉시 돈이 새는" 구멍은 아니지만, 보상 경제의 입력 데이터 자체를 못 믿게 된다.
6. **닫힘 확인**: ① 구 키로 `POST /api/sre/sreMessage` 호출 시 **401** ② 신규 토큰이 타 사용자 device 로 주입 시도 시 거부 ③ 신규 앱에서 정상 GPS ingest 확인.

### 1-3. 법무 — 외부 자문 미수령 + P-3 보존 근거 공란 + Q1~Q9 — B-6 (게이트 4 잔여)

1. **무엇인가**: 개인정보처리방침·이용약관을 실제 시스템 동작에 맞게 전면 수정한 **초안**이 앱에 들어가 있다(P-1~P-11·T-1~T-3 불일치 전수 해소, [`260802_legal_review_request.md`](./260802_legal_review_request.md)). 화면에 노출되던 "[법무 검토 전 초안]" 표식은 대표 승인으로 제거했다(2026-08-02). **그러나 표식 제거는 검토 완료가 아니다** — 외부 법률 자문은 여전히 받지 않았고, P-3(법령·계약상 보존이 필요한 정보의 **근거 조문·보존 기간**)은 일반 서술로만 남아 있으며, 법무가 답해야 할 질문 Q1~Q9(개정 시행일·해시 아카이브의 법적 성격·수탁사 실명/국외이전·타인 콘텐츠 연쇄 삭제·복구 경로 형평 등)가 전부 미답이다.
2. **왜 지금 못 닫는가** — **외부 승인(법률 판단)**: 베트남 PDPD(Nghị định 13/2023)·전자상거래·소비자보호법상 보존 의무 조문과 기간, 해시 보관의 익명/가명 판정 등은 법률 자문 자격이 필요한 판단이다. 작성자(개발)는 자격이 없어 지어 넣을 수 없다 — 지어 넣으면 그게 더 큰 리스크다.
3. **선행조건**: 외부 법률 자문(베트남 현지법) 계약·회신. 회신 후 반영은 **코드 변경 없이 문안(`legal.privacyHtml`/`termsHtml` 3로케일)만 바꾸면 된다** — 개발 작업량 반나절 이하.
4. **누가**: 대표(자문 의뢰) → 법무(회신) → 개발(문안 반영).
5. **안 닫으면**: ⓐ 방침이 공표한 보존·파기 서술의 법적 근거가 비어 있는 채 실사용자 동의를 받게 된다 — 분쟁·감독기관 조사 시 "근거 조문 없는 무기한 익명화 보존"이 방어 불가가 될 수 있다. ⓑ 해시 아카이브 1년 보관이 현지법상 가명정보로 판정되면 별도 고지·동의 요건 위반이 소급된다. ⓒ 한국 서버 호스팅이 PDPD 국외이전 고지 대상인데 미고지라면 방침 전체의 적법성이 흔들린다. 전부 **출시 후 고치면 기존 동의를 다시 받아야 하는** 성격이라 출시 전에 닫는 것이 압도적으로 싸다.
6. **닫힘 확인**: ① Q1~Q9 답변 문서 수령 ② P-3 조문·기간이 문안에 기입 ③ 개정 시행일·재동의 절차 확정(동의 버전 캡처 인프라는 이미 있음 — `163_user_consent_capture.sql`) ④ 3로케일 반영 후 의미 동일 확인.

### 1-4. Apple 로그인 미구성 — iOS 출시 한정 차단

1. **무엇인가**: Apple 로그인 시크릿이 DB `app_config` 에 아직 `CHANGE_ME` 다(2026-08-02 기준, [`260801_owner_action_items.md`](./260801_owner_action_items.md) D 절). Zalo 는 운영 동작 확인 완료(대표 실기), Google 은 콘솔 URI 등록 + 토큰 엔드포인트 판별로 client_id·활성 시크릿 검증 완료 — **Apple 만 미구성**이다.
2. **왜 지금 못 닫는가** — **외부 자격**: Apple Developer 콘솔에서 Services ID·개인 키 발급과 Return URL 등록이 필요하다. 개발 권한으로 할 수 없다.
3. **선행조건**: ① Apple Developer 계정에서 Sign in with Apple 키 발급 ② Services ID 의 Return URL 에 `https://app.saigon-rider.com/api/bff/auth/oauth/apple/callback` 등록(콜백 SoT 는 `BFF_PUBLIC_URL` 하나 — ADR "OAuth 콜백 도메인" 절) ③ `app_config` 값 주입(BFF 재시작 불필요 — 요청마다 DB 를 읽는다).
4. **누가**: 대표(콘솔) + 개발(주입 후 실측).
5. **안 닫으면**: iOS 출시가 불가능하다 — **App Store 심사 지침상 제3자 소셜 로그인(Zalo/Google)을 제공하는 앱은 Sign in with Apple 을 함께 제공해야 한다.** Android 는 Apple 로그인을 이미 숨기므로(2026-07-06 대표 결정: iOS 전용) **Android 단독 출시라면 §2 로 내려가는 항목**이다 — 출시 플랫폼 결정에 따라 긴급도가 갈린다.
6. **닫힘 확인**: iOS 실기기(또는 Safari)에서 Apple 로그인 → 세션 발급까지 1회 통과. 미구성 상태 확인은 `app_config` 의 apple 시크릿이 `CHANGE_ME` 인지 조회.

### 1-5. 운영 `WITHDRAWN_HASH_PEPPER` — 키 자체가 없다 (본 문서 작성 중 실측·**기존 서술 정정**)

1. **무엇인가**: 탈퇴회원 식별자(전화번호·OAuth ID)를 HMAC 해시로 1년 보관하는 부정이용 방지 장치(대표 결정, `170_withdrawn_member_archive.sql`)의 비밀 재료(pepper)다. **2026-08-02 실측(ssh saigon-prod, 키 이름만 대조·값 미출력): 운영 `.env` 에 `WITHDRAWN_HASH_PEPPER` 키가 아예 없다.** 최종보고서 v2 §7 의 "dev 값만 넣었다"는 서술보다 상태가 나쁘다 — 키 부재다. 같은 대조에서 `BACKUP_*` 6키도 부재(1-6 참조). 원인: 2026-08-02 오전의 운영 키셋 동기화(9키) **이후** 커밋(`cac7c23`·`48e25ba`)이 `.env.example` 에 7키를 추가했는데 운영 `.env` 에 재반영되지 않았다 — "키셋 동일" 규약이 재위반된 상태다.
2. **왜 지금 못 닫는가** — **운영 설정(값 생성이 대표 소관)**: pepper 는 한 번 정하면 바꿀 수 없는 비밀값이다(바꾸면 기존 해시 전부 무효). dev 값을 복사하면 안 되고(운영 별도 값), 값 결정·보관이 대표 몫이다.
3. **선행조건**: `openssl rand -hex 32` 등으로 운영 전용 값 생성 → 운영 `.env` 에 키 추가 → bff 재기동. 5분 작업.
4. **누가**: 대표(운영 서버 접근·값 보관).
5. **안 닫으면**: pepper 미설정 시 아카이브는 **fail-open** 으로 조용히 건너뛴다(탈퇴 자체는 정상 진행 + 에러 로그) — 즉 운영에서 탈퇴가 발생하는 순간부터 ⓐ 방침이 공표한 "해시 1년 보관"이 **실제로는 일어나지 않아** 공표-실동작 불일치가 다시 생기고(게이트 4 를 닫은 근거가 무너진다), ⓑ 재가입 부정이용 추적이 공백이 되며, ⓒ 그 기간의 탈퇴 건은 소급 캡처가 불가능하다(원본을 안 남기므로). 어드민 `withdrawn-check` 조회도 503 을 낸다.
6. **닫힘 확인**: ① 운영 `.env` 에 키 존재(값 미출력, `grep -c` 로 유무만) ② 운영에서 테스트 계정 탈퇴 1회 → `withdrawn_member_archive` 행 생성 확인 ③ 어드민 `GET /admin/api/users/withdrawn-check` 가 503 이 아닌 정상 응답.

### 1-6. S3 오프사이트 백업 — 자격증명·암호화 키 미설정 (게이트 9 잔여, B-5)

1. **무엇인가**: DB 백업을 서버 밖(S3 호환 스토리지)에 암호화해 복제하는 기능. **코드는 완비·검증 완료**다(MinIO 라운드트립 SHA-256 일치 실증 — [`260802_backup_restore_drill.md`](./260802_backup_restore_drill.md) §5). env 6키(`BACKUP_S3_*` 5종 + `BACKUP_ENCRYPTION_KEY`)가 비어 있어 **오프사이트 단계만 무동작**이고, 로컬 백업(매일 02:30 ICT, 14일 보존)은 이미 돈다. 1-5 실측에서 확인했듯 **운영 `.env` 에는 이 6키가 키 이름조차 없다.**
