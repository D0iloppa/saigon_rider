## 1. 핵심 판단

현재 화면은 큰 업체 사진과 정보 수정, 사업자 검증, 가이드, 소식, 가격표, 매물, 광고가 길게 이어진다. 파트너가 우선 알아야 할 **현재 처리할 일과 광고 상태**가 뒤로 밀리고, 성과·후기는 별도 대시보드의 하단에 있다. 단순 색상 교체보다 정보의 순서를 바꾸는 것이 효과가 크다.

설계 방향은 **작은 가게 식별부 → 지금 필요한 행동 → 광고 상태 → 일상 관리**다. 성과는 별도 탭에서 기간과 지표 정의를 분명하게 유지한다. 기존 따뜻한 배경·선명한 글자·절제된 오렌지의 제품 언어를 그대로 사용한다.

가장 먼저 고쳐야 하는 것은 상태의 정확성이다. 현재 소재 승인만으로 `게시중`을 표시하며, `문의`라는 숫자는 실제로 전화·단골·찜·후기 행동 합계다. 시안은 이 두 의미를 정직하게 분리한다.

## 3. 정보구조와 행동 배치

탭은 기존 두 탭을 유지하며 사용자 언어로 `운영` / `성과`를 제안한다. 새 최상위 메뉴나 영구 탭바를 만들지 않는다. 모든 모드 상단에 현재 업체가 남아야 한다.

### 운영 탭 — 390px 기준

1. 기존 TopBar 문법: 뒤로가기 + `파트너 라운지`. 시안의 뒤로가기는 검토용 이전 패널로만 복귀.
2. 업체 식별부: 56×56 썸네일 또는 Store 아이콘, 업체명 18px/700, 업종·지역 한 줄 12px. 검증 완료인 경우에만 검증 체크. 다업체일 때 업체명 옆 chevron으로 선택 시트. 아래 `내 가게 보기` / `정보 수정` 중립 텍스트 버튼.
3. `운영 | 성과` 언더라인 탭. 탭 높이 48px.
4. 조건부 행동 카드: 검증 전/반려/입금대기처럼 명확한 조치가 있으면 위로. 제목 18px/700, 설명 13px/1.5, 주 버튼 높이 46px. 처리할 일이 없는 정상 상태에는 거대한 축하 배너나 임의 점수를 만들지 않는다.
5. `광고 관리` 섹션: 한 장의 카드 안에 광고 제목, 소재 심사·계약 상태, 게시 기간(있을 때), 중립 상세 버튼. 광고가 없으면 `아직 광고가 없어요`와 짧은 설명. 페이지 내에 우선 조치가 없을 때만 `광고 등록`을 오렌지 주 CTA로 둔다.
6. `가게 운영` 묶음: 소식 관리 / 가격표 / 매물 등록 / 후기 관리 네 행. 한 카드, 행간 구분선, 각 행 60~68px, 아이콘 20px 중립색, 제목 15px/600, 설명 12px. 실제 확인되지 않은 총 개수·미답변 배지 없음.
7. 검증이 완료되었거나 심사 중이면 조용한 사업자 검증 행. 상단 조치 카드에 이미 등장한 경우 같은 장문을 반복하지 않는다.
8. `파트너 가이드` 아코디언과 `광고 관련 도움` 중립 행. 가이드는 운영 정보 아래.

광고가 여러 개면 우선 조치가 필요한 광고를 먼저 보여주되, `입금 대기` 자체가 광고 미노출이라는 가정을 넣지 않는다. 전체 목록은 같은 시안 내 광고 패널로 이어진다. 구현 시 현재 모든 광고 목록은 이미 fetchBusinessAds로 취득 가능하다.

### 성과 탭

- 시작: `광고 성과` 20px/700, 아래 실제 선택 기간과 `베트남 시간 기준` 12px 보조 라벨. 7일 / 14일 / 30일 단일 선택기가 전체 지표·차트를 함께 바꾼다.
- 세 지표 `노출`, `클릭`, `고객 행동`을 하나의 흰 카드 안 3열로 배치한다. 숫자 24~28px, 숫자용 Space Grotesk 최대 700. 좁은 360px에서 단위·큰 숫자가 넘치면 24px로 줄이며 숫자 생략 금지.
- `고객 행동` 옆 설명 버튼: `전화·단골 추가·찜·후기 행동의 합계예요. 실제 문의 완료나 구매 건수를 뜻하지 않아요.`
- 추이의 기본 선택은 노출. `노출 | 클릭 | 고객 행동` 선택 후 하나의 차트를 보여준다. 기존 API series의 같은 기간 데이터를 소비할 수 있는 시각적 재구성이다. 한 그림에 이중 Y축을 넣지 않는다. 접근 가능한 `표로 보기` 토글 유지.
- 추가 지표(CTR/CVR·비용)는 `자세히 보기` 아래. 기준치 미달이면 비율을 숨기고 이유만 설명한다. 이 기준치는 서버 minSampleForRatio를 그대로 쓴다.
- 업체 지표(후기·단골)는 별도의 구역으로 내려 광고 성과와 혼합하지 않는다. 소식 수는 총 개수가 확인되지 않아 제외한다.
- 후기 관리는 운영 탭에서 접근하고 성과 하단에도 중립 링크를 둘 수 있다. 후기 작성/수정·신고는 기존 공용 기능을 연결하는 계획이다.
- `no_ads`, `pending`, `warming_up`, `low_sample`, `normal`, `선택 기간 0`, `조회 실패`를 서로 다르게 렌더한다. 집계 전 상태에 보기 좋은 가짜 상승 그래프를 그리지 않는다.

| 실제 0 | `선택 기간에 기록된 노출이 없어요` + 기간 유지 | 다른 기간 선택 | API 성공의 0을 오류로 간주 금지 |

소재 심사 상태 / 계약 상태 / 노출 상태는 별개의 축이다. 정식 제품 구현에서 서버의 권위 있는 노출 판정·사유를 보내지 않으면, UI는 `소재 승인` 등 확인 가능한 정보만 말해야 한다. 본 디자인 티켓이 새 결제 API나 정책 변경까지 승인한 것으로 보지 않는다.

## 7. T3 프로토타입 구현 지시

산출물은 감독이 지정한 `ai-docs/task/active/260908_partner_lounge_ui/prototype.html`. HTML/CSS/JS 로컬만으로 동작한다. 새 패키지·외부 CDN 의존을 추가하지 않는다. 복사한 토큰은 출처 주석을 남긴다. 제품 src를 수정하지 않는다.

필수 화면은 운영 홈, 성과, 업체 선택, 정보 수정, 광고 상세/계약 안내, 후기 패널이다. 소식·가격표·매물은 기존 화면으로 연결될 내용과 CTA를 보여주는 가벼운 로컬 패널이면 충분하다. 각 아이콘·버튼은 진짜로 패널/시트/상태를 바꾸고, 뒤로가기·닫기로 돌아올 수 있어야 한다. 네트워크 요청·실제 제출은 없다.

기본 상태는 `검증 완료 + 광고 없음 + 아직 집계 없음`을 권장한다. 특정 운영 업체가 실제로 이 상태라는 뜻이 아니며 빈 상태의 완성도를 첫 시안에서 확인하는 목적이다. 검토 프레임에 `디자인 시안 · 샘플 상태 · 실제 계정/결제와 연결되지 않음`을 상시 표시한다.

상태 선택기는 최소 `검증 전`, `검토 중`, `광고 없음`, `입금 대기`, `노출 중(샘플)`, `중단`, `계약 만료`, `통계 오류`, `로딩`을 제공한다. 입금 대기에서 노출 여부를 단정하지 않는다. 정상 노출은 시안 안에서만 명시적으로 정의된 fixture이며 현재 제품 API가 그 정보를 보장한다고 쓰지 않는다.

성과 수치를 넣어 비교 시각화가 필요하면 반드시 `샘플 성과`를 차트 옆에도 표시한다. 날짜·시계열·합계는 결정적 배열에서 계산하고 7/14/30일 변경 시 수치와 날짜를 모두 갱신한다. 모호한 랜덤 생성·고정 상승률·실제 파트너처럼 보이는 수치 금지. 실적을 넣지 않는 상태에서는 `—`와 원인을 표시한다. 연관 없는 예약/매출/지출 추정은 추가하지 않는다.

시안 폼에 가시적 label, 필수 입력 오류, 저장 중 disabled 상태를 넣는다. 모달은 dialog 의미론, Escape 닫기, 내부 포커스 유지·닫은 뒤 트리거 복귀. 탭은 role/aria-selected/키보드 이동 또는 명확한 동등 접근을 제공한다. 상태/선택을 색에만 의존하지 않는다. 버튼 내부 버튼 금지.

7. 브라우저 검증이 불가능하면 정적 검증 범위를 그대로 보고하고 실제 캡처를 했다고 주장하지 않는다.
